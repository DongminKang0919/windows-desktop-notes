## WM-001: 개발 환경 확인 및 최소 WPF 시제품 준비

- 문제: 기술 검증에 사용할 실행 가능한 창이 없다.
- 범위: 환경 확인, C# + WPF 최소 프로젝트, 입력 가능한 창 하나.
- 인수 조건:
  - [x] 사용 가능한 SDK와 검증 대상 Windows 환경을 기록한다.
  - [x] 선택한 .NET 버전과 선택 이유를 기록한다.
  - [x] 프로젝트가 빌드되고 실제 Windows에서 실행된다.
  - [x] 창에서 한글과 여러 줄 텍스트를 입력할 수 있다.
  - [x] 확인한 빌드·실행 방법과 실제 파일 구조를 README에 반영한다.
- 검증 방법: 빌드 및 실제 창 입력 확인.
- 검증 환경: Windows 빌드 26200.9457, x64, SDK 10.0.401. .NET 10 LTS와 설치된 최신 SDK를 기준으로 선택.
- 결과 및 증거: Release 빌드·실제 앱 실행·사용자 한글 입력 확인. 상세는 results/SPRINT-01.md.
- 환경 확인: SDK는 기본 경로에 설치되어 있으며 현재 Codex 셸의 PATH만 미갱신되어 절대 경로를 사용.
- 제외 범위: 바탕화면 부착, 영구 저장.

## WM-002: 바탕화면 부착 동작 검증

- 문제: 바탕화면 보기를 눌러도 메모가 남아 있어야 한다.
- 범위: WM-001의 창을 이용한 Windows 연동 시제품.
- 인수 조건:
  - [x] 다른 프로그램이 메모와 겹치면 메모가 그 뒤에 놓인다.
  - [x] 작업 표시줄의 바탕화면 보기를 눌러도 메모가 보인다.
  - [x] Win+D를 눌러도 메모가 보인다.
  - [x] 바탕화면 보기 상태에서 클릭하여 한글 및 여러 줄 내용을 편집할 수 있다.
  - [x] 부착 상태에서 굵게·글자 색상·글머리 및 번호 목록을 적용·해제할 수 있다.
  - [x] 서식 도구 클릭 시 본문 선택과 한글 입력 포커스가 정상적으로 유지된다.
  - [x] Win+D를 다시 눌러 창을 복원하면 메모가 다른 프로그램 뒤에 놓인다.
  - [x] 연동 방식, 검증 환경, 통과·실패 결과와 제한사항을 기록한다.
- 검증 방법: 실제 Windows에서 위 동작을 순서대로 수행하고 기록.
- 검증 환경: 사용자 Windows 11 PC, 빌드 26200.9457, x64.
- 결과 및 증거: 실제 창 생성·해제, 자동 서식 명령, 사용자 확인 2건으로 바탕화면 보기·입력·서식·창 복원 및 아이콘 동작 확인. results/SPRINT-01.md 참고.
- 제외 범위: 탐색기 재시작 복구, 여러 모니터 지원, 저장.

## 후속 작업

아래 작업은 방향만 정해진 Backlog다. Ready로 옮기기 전에 범위와 인수 조건을 구체화한다.

- **WM-003:** 탐색기 재시작 후 재부착, 모니터 추가·제거, 서로 다른 배율에서 위치와 입력 검증.
- **WM-004:** RTF와 상태를 포함한 계정 기반 암호화 봉투 저장 검증, 자동 저장과 재실행 시 서식·위치·숨김 상태 복원, 실패 시 원본·백업 보호. REQUIREMENTS.md의 AC-06 및 AC-09, SECURITY.md의 암호화 규칙을 작업 조건으로 구체화한다.
- **WM-005:** Git 초기화, 원격 저장소 결정, GitHub Projects 상태 및 이슈 연결. 연결 후 보드로 상태 관리 이동.
  - 진행: main 브랜치 초기화 및 사용자 GitHub 저장소를 origin으로 연결. GitHub Projects 보드·이슈 연결은 후속 작업으로 남는다.
- **WM-006:** 실제 프로젝트에 맞는 빌드 CI. 자동 테스트가 생기면 함께 실행하고 바탕화면 수동 검증은 별도 기록.
- **WM-007:** 여러 메모 관리, 닫기 시 숨김과 트레이 복원, 앱 종료 및 단일 실행 인스턴스. AC-07을 기준으로 세분화한다.
- **WM-008:** 앱 휴지통으로 이동·복원·확인 후 영구 삭제. 자동 비우기는 하지 않으며 AC-08을 기준으로 한다.
- **WM-009:** 기본 꺼짐인 로그인 자동 실행 옵션. AC-10에 따라 실제 로그인 결과를 검증한다.
- **WM-010:** 버전 공통 설정, 설치 및 업데이트 패키징, 자동 확인·다운로드와 저장 후 적용. RELEASES.md의 인수 조건을 기준으로 세분화한다. 실제 설치본 두 버전으로 데이터 보존과 실패 경로를 검증한다.
- **WM-011:** SECURITY.md에 따라 DPAPI 봉투·입력 크기·스키마·경로·붙여넣기·로그 및 의존성을 검증한다. 관련 기능 구현 시 함께 작업하고 보안 검토만 마지막에 몰아서 하지 않는다.
- **WM-012:** STABILITY.md에 따라 창·훅·이벤트·타이머의 해제, 반복 시 힙·핸들·CPU와 8시간/배포 전 24시간 시험 결과를 기록한다. 시제품부터 기본 상태를 측정한다.

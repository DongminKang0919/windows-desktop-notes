# 데스크톱에서 8/24시간 사용 기록하기

이 ZIP은 개발 시험용 Windows x64 메모 앱과 별도 감시 도구를 담고 있다. .NET 런타임을 포함하므로 대상 PC에 SDK나 런타임을 따로 설치하지 않아도 된다. 디지털 서명은 아직 없으므로 Smart App Control이 켜진 PC에서는 차단될 수 있다. 도구가 Windows 보안 설정을 변경하지 않는다.

## 시작

1. ZIP 전체를 데스크톱 PC의 쓰기 가능한 폴더에 압축 해제한다. ZIP 안에서 바로 실행하지 않는다.
2. 다른 경로에서 실행 중인 Windows 메모가 있으면 트레이의 **모든 메모 저장 후 종료**로 종료한다. 도구는 다른 경로의 앱을 강제 종료하거나 감시 대상으로 바꾸지 않는다.
3. **Start-8h.cmd**를 더블클릭한다. 앱과 감시 콘솔이 함께 실행된다. 먼저 8시간을 확인한 뒤 **Start-24h.cmd**로 24시간 시험한다. 두 감시 콘솔을 동시에 실행할 필요는 없다.
4. 평소처럼 사용한다. 기본 수집 간격은 10초이고 현재 값은 콘솔에 약 1분마다 표시한다. 콘솔 창은 최소화해 두어도 된다.
5. 종료할 때 감시 콘솔에서 **Q** 또는 **Ctrl+C**를 누른다. 감시만 끝나며 메모 앱은 유지된다. 콘솔의 X를 누르면 최종 보고서 갱신이 생략될 수 있으나 이미 기록된 JSONL은 남는다.

메모는 이 데스크톱 계정의 기존 `%LOCALAPPDATA%\WindowsMemo\Notes`를 사용한다. ZIP에 노트북의 메모는 포함되지 않는다. 노트북의 암호화 파일을 복사하는 방식으로 메모를 이전하지 않는다.

## 사용 구간 표시

감시 콘솔에 포커스를 두고 다음 키를 누른다. 전역 단축키가 아니므로 메모를 편집하며 같은 글자를 입력해도 동작하지 않는다. 최대 10초 뒤 반영된다.

- **I**: 유휴 구간. 밤새 입력 없이 켜 둘 때 누른다.
- **A**: 사용 구간. 다시 편집하거나 창을 반복해서 여닫을 때 누른다.
- **M**: 문제 관찰 시각 표시. 멈춤·사라짐·입력 지연 등을 느낀 순간 누르고 별도로 증상을 적어 둔다. 도구는 증상 내용이나 메모 본문을 받지 않는다.
- **Q**: 감시 종료 및 최종 보고서 생성.

시작 후 약 5분은 런타임 준비 구간으로 둔다. 메모 수와 본문 크기가 크게 바뀌면 메모리도 바뀌므로, 작업을 마친 뒤 비슷한 상태로 돌아와 유휴 구간을 비교한다. 8시간 동안 같은 상태로 계속 실행한 시험을 원하면 전원을 연결하고 절전 시간을 확인한다. 도구는 절전을 막지 않으며 절전/복귀·표본 지연을 공백 이벤트로 기록한다. PC 재부팅·로그아웃은 감시도 종료하므로 로그인 후 새 감시 세션을 시작한다.

## 남는 파일

실행한 폴더의 `logs/날짜-시각-고유번호/`에 각 시험을 따로 보관한다.

| 파일 | 내용 |
| --- | --- |
| report.html | 브라우저에서 여는 그래프·요약. 5분마다, 정상 감시 종료 때 갱신 |
| summary.json | 실행 구간별 메모리·CPU·핸들 요약, 기계 분석용 |
| samples.csv | Excel 등에서 읽는 10초 간격 수치 |
| samples.jsonl | 각 표본의 원본 기록. 한 줄씩 저장 |
| events.jsonl | 앱 발견·종료·재시작·표본 공백·구간 표시·문제 시각 |
| session.json | 앱 경로, OS·CPU 수, 수집 조건. 실행 시 앱 버전과 EXE/DLL SHA256도 이벤트에 기록 |

분석할 때는 **해당 logs 세션 폴더 전체를 ZIP으로 묶어서 전달**하면 된다. 앱 파일이나 실제 메모 저장 폴더는 필요 없다. `session.json`의 실행 경로에는 Windows 사용자 이름이 포함될 수 있으니 공유 전에 확인한다. 도구가 자동 전송하거나 이전 로그를 자동 삭제하지 않는다.

최종 보고서가 없거나 감시를 비정상 종료했다면 PowerShell에서 다음 명령으로 다시 만든다. 기존 원본 로그는 변경하지 않으며, 끝의 불완전한 JSON 줄은 제외한 개수를 보고한다.

```powershell
& '.\monitor\WindowsMemo.Monitor.exe' --report '.\logs\해당-세션-폴더'
```

## 수치 해석과 한계

- **Private MiB**: 프로세스가 전용으로 할당한 메모리. **Working Set MiB**: 현재 물리 메모리 점유량. 캐시·JIT·GC와 OS의 관리에 영향을 받으므로 한 번 증가한 것만으로 누수라고 판단하지 않는다.
- **CPU %**: 논리 CPU 전체 기준의 구간 평균. 유휴 평균은 I로 표시한 구간만 포함한다. 절전·큰 측정 공백 직후에는 CPU 값을 비워 왜곡을 피한다.
- **Handles / GDI / USER / Threads**: 창·이벤트·파일 등의 자원 증가 단서. 관리 힙만 확인해서 놓칠 수 있는 자원 누수를 함께 본다.
- **UI timeout**: WPF 창의 WM_NULL 메시지에 250ms 내 응답했는지 보는 참고 지표. 오래 걸리는 작업이나 대화상자 때문에 발생할 수도 있다. 메모가 실제 보이는지·입력이 되는지·저장이 성공했는지는 직접 확인해야 한다.
- 앱이 종료되면 종료 시각과 가능한 종료 코드를 남기고, 같은 EXE 경로에서 다시 실행되면 새 구간으로 수집한다. 강제 재시작·강제 GC·메모리 축소를 하지 않는다. 이름만 같은 다른 경로의 앱은 합치지 않는다.
- 경과 시간과 CPU를 실제로 계산한 표본 구간 합계를 구분한다. 절전한 8시간을 연속 사용 시험 통과로 보지 않는다.
- 메모 본문·제목·키 입력·화면·클립보드·메모 파일·덤프·Windows 전체 이벤트 로그는 수집하지 않는다. 앱 내부 예외 스택이나 GC 객체 참조는 이 도구로 알 수 없다. 추세나 종료 이상을 찾으면 해당 구간을 기준으로 추가 진단한다.

시험 중 앱이 사라지거나 입력이 멈췄다면 M으로 시각을 표시하고, 당시 조작·메모 개수·절전/Win+D 여부를 따로 메모해 두면 원인을 좁히기 쉽다. 개인 메모 본문은 분석 자료에 포함하지 않는다.

개발 폴더에서 감시만 실행할 때:

```powershell
& '.\tools\WindowsMemo.Monitor\bin\Release\net10.0-windows\WindowsMemo.Monitor.exe' --exe '.\src\WindowsMemo\bin\Release\net10.0-windows\WindowsMemo.exe' --duration-hours 8 --output '.\artifacts\long-run-logs'
```

패키지 재생성: `scripts/package-desktop-test.ps1`. 공식 .NET 10 런타임 10.0.15를 포함하는 self-contained publish를 사용한다. 빌드·자동 검사 후에만 ZIP을 만들며 사용자 메모·기존 logs는 포함하지 않는다. 모니터 빌드·보고서 회귀 검사는 Windows CI에도 연결한다.

측정 규약: [Process.PrivateMemorySize64](https://learn.microsoft.com/en-us/dotnet/api/system.diagnostics.process.privatememorysize64), [GetGuiResources](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-getguiresources).

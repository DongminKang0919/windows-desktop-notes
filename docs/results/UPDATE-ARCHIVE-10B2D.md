# WM-010B2D: 앱 업데이트 아카이브 경로 검사 보완

2026-10-23. 깨끗한 작업 트리와 `git fetch origin`으로 PR #17 병합 main `cdb7506` / 0.9.15를 확인했다. `fix/update-archive-layout` 브랜치에서 0.9.16으로 작업했다.

## 문제와 변경

0.9.15의 배포 검증 스크립트와 달리 앱의 `UpdatePackageValidator`는 파일을 다른 항목의 부모로 쓰는 경로를 거부하지 않았다. `TrimEnd('/')`가 반복 끝 구분자를 모두 지웠고, Windows 예약 이름의 위 첨자 숫자·확장자 앞 공백과 디렉터리 데이터/속성 불일치도 놓쳤다. 이 발견은 코드 검토 결과이며 수정 전 실행 실패 재현은 아래 정책 차단으로 미완료다.

- 파일/디렉터리를 대소문자 무시 사전에 기록하고 전체 항목을 읽은 뒤 부모 경로를 검사한다. 자식이 먼저 나와도 파일 부모를 거부한다. 명시적 디렉터리 헤더 없이 부모 폴더를 사용하는 정상 ZIP은 허용한다.
- 끝의 디렉터리 표시 하나만 제거해 반복 구분자와 빈 구성요소를 거부한다.
- 기존 예약 이름 검사에 COM/LPT 위 첨자 1/2/3과 확장자 앞 공백을 추가한다.
- 디렉터리의 비어 있지 않은 데이터, 디렉터리 속성인데 끝 `/`가 없는 항목, Unix 일반 파일 속성인데 끝 `/`가 있는 항목을 거부한다. 기존 링크/특수 파일·재분석 속성 검사도 유지한다.

기존 다운로드 후·적용 직전 검사 호출 지점을 그대로 사용한다. 항목 512개, 개별 256MiB, 합계 512MiB, 해시·제품/버전·XML 제한을 유지한다. 배포 스크립트의 크기 한도를 앱에 이식하는 변경은 아니다. 메모 저장 스키마 4·DPAPI·복구 ID·캐시 교체 동작은 변경하지 않았다. 새 의존성·이벤트·타이머·상주 작업은 추가하지 않았으며 경로 사전은 기존 512개 항목 한도 안에서만 유지한다.

## 회귀 검사와 로컬 결과

기존 실행형 하네스에 합성 패키지 검사 5개를 추가했다. 정상 명시적/암시적 디렉터리·항목 순서·예약 이름과 비슷한 정상 파일명·한글 파일명, 파일 부모 충돌 양방향/대소문자, 예약 이름 변형, 디렉터리 데이터/속성·파일/폴더 충돌, 반복 구분자를 다룬다. 각 거부 fixture의 크기·SHA256도 다시 계산해 경로 검사까지 도달하도록 구성했다. 거부 전후 패키지 바이트 보존도 확인하도록 작성했다. 가짜 EXE/DLL은 실행하지 않으며 추출·설치하지 않는다.

```powershell
dotnet build WindowsMemo.slnx --configuration Release --nologo --artifacts-path artifacts/update-archive-validation -p:RestoreLockedMode=true
dotnet artifacts/update-archive-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll
```

- Release 빌드: 경고 0·오류 0. 기본 src/tests 출력과 분리한 artifacts를 사용했다.
- 최초 빌드는 샌드박스가 사용자 NuGet.Config 읽기를 거부했다. 승인된 권한 확장 빌드에서 잠금 복원과 컴파일을 완료했다.
- 실행형 하네스: 수정 전/후 모두 Windows 애플리케이션 제어 정책으로 DLL 로드가 차단됐다(`FileLoadException`, `0x800711C7`, 종료 코드 1). **신규 5개와 기존 검사의 이번 버전 실행 결과는 미검증**이다. 정책 변경·우회 실행은 하지 않았다.
- `git diff --check`: 통과. 원격 푸시·CI 실행은 하지 않았다.

## 남은 확인

허용된 Windows 환경의 기존 CI로 회귀 실행을 확인해야 한다. 실제 Velopack 설치본 패키지와의 호환성·두 버전 업데이트·데이터 보존, 게시자 인증·서명, 동일 계정의 파일 교체 경쟁, Windows 셸/로그아웃·다중 DPI와 8/24시간 상주 검증은 남아 있다. 빌드 성공으로 업데이트 적용·보안·장시간 안정성 완료를 판정하지 않는다.

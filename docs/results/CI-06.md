# WM-006 Windows 빌드 CI 검증

- 날짜: 2026-10-13
- 상태: Review — 구현·로컬 검증 완료, GitHub Actions 실행 검증 대기
- 기준 버전: 0.3.0 / .NET SDK 10.0.401

## 구성

`.github/workflows/windows-ci.yml`에서 main 푸시, main 대상 PR, 수동 실행을 지원한다. Windows 호스팅 러너에 global.json 기준 SDK를 설치하고 Release 빌드 후 테스트 실행 프로그램을 실행한다. 기존 테스트는 별도 프레임워크가 없는 실행 프로그램이므로 dotnet test를 사용하지 않는다. 읽기 전용 contents 권한, 체크아웃 인증 정보 미보존, 15분 작업 제한과 같은 ref의 이전 실행 취소를 적용한다.

GitHub 공식 [setup-dotnet](https://github.com/actions/setup-dotnet) 및 [checkout](https://github.com/actions/checkout) 사용법을 확인해 각각 v6, v7을 사용했다. SDK 다운로드 및 호스팅 러너에서 WPF 검증이 가능한지는 첫 원격 실행에서 확인해야 한다.

## 로컬 결과

```powershell
dotnet build WindowsMemo.slnx --configuration Release --nologo
dotnet tests/WindowsMemo.Tests/bin/Release/net10.0-windows/WindowsMemo.Tests.dll
```

- Release 빌드: 경고 0, 오류 0, 종료 코드 0
- 자동 검증: 26개 PASS, 종료 코드 0
- git diff --check: 통과
- 테스트 데이터는 기존 테스트의 bin 하위 폴더를 사용하며 사용자 메모 폴더를 사용하지 않는다.

기본 터미널 초기화 오류로 대체 로컬 실행 경로를 확인했다. 해당 경로는 NuGet 사용자 설정 접근 제한으로 복원에 실패해, 승인된 PowerShell 실행에서 빌드와 테스트를 완료했다. 이 실행 환경 문제 때문에 프로젝트 코드나 SDK 설정을 변경하지 않았다.

## 남은 검증

- 원격 푸시는 이전 사용자 보류를 유지했다. GitHub Actions의 실제 실행 성공은 아직 확인하지 않았다.
- --shell-probe는 로그인된 바탕화면을 요구하므로 CI에서 실행하지 않는다. 기존 27개 기록은 이 검증을 포함하고, 이번 CI 명령은 26개다.
- WM-003/004의 실제 탐색기 재시작·다중 모니터·앱 종료 및 재실행·저장 실패 UI 검토는 여전히 Review다.
- Win+D·실제 한글 조합·절전 복귀·장시간 상주는 이번 자동 검증 범위에 포함하지 않는다.

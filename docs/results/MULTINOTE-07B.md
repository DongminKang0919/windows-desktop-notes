# 0.4.0 여러 메모·트레이·숨김/복원 검증

- 날짜: 2026-10-13
- 작업: WM-007A 후속 검증 및 WM-007B
- 상태: Review — 구현·자동 검증 완료, 실제 UI 검토 대기
- 환경: Windows 빌드 26200.9457 / x64, .NET SDK 10.0.401

## 동작

메모의 새 메모 버튼과 트레이 메뉴에서 메모를 생성한다. 메모 목록은 메모 버튼·트레이 메뉴·트레이 더블클릭으로 연다. 목록은 본문 대신 ID 앞 8자리와 표시·숨김·복원 실패 상태를 보여 준다. 새 메모는 위치를 조금씩 달리 배치한다. 표시 중인 메모를 목록에서 열면 창을 중복 생성하지 않는다.

닫기는 최신 본문·서식·위치·크기와 Hidden=true를 같은 암호화 레코드로 저장한 뒤 창·편집기·자동 저장 서비스를 폐기한다. 실패하면 숨김을 취소하고 최신 편집기를 유지한다. 마지막 메모를 숨겨도 트레이는 유지한다. 다시 열기는 파일에서 편집기를 재생성하고 표시 상태를 저장한다. 표시 상태 저장 실패는 편집기를 유지하고 재시도 상태를 안내한다.

앱 시작 시 표시 중이던 메모만 연다. 전부 숨김 또는 오류면 목록을 연다. 한 메모를 복원하지 못해도 그 파일을 덮어쓰지 않고 정상 메모를 연다. 트레이의 모든 메모 저장 후 종료는 보이는 메모 모두 저장을 시도하고 하나라도 실패하면 종료를 취소한다. 단일 실행 Mutex는 기존 이름을 유지한다.

## 저장 호환성

앱 버전은 공통 설정의 0.4.0이다. 숨김 상태를 포함하는 내부 스키마 2로 저장하며 스키마 1의 Hidden 없는 파일은 표시 상태로 읽는다. DPAPI CurrentUser 봉투 버전 1, 기존 고정 ID의 파일명과 데이터 루트는 유지한다. 기존 파일은 첫 정상 저장 때 이전본을 백업으로 남긴다. 읽는 앱보다 새로운 스키마는 손상으로 처리하여 이전 백업으로 되돌리지 않고 원본을 보존한다. 0.4.0으로 저장한 데이터를 0.3.0에서 다시 사용하는 다운그레이드는 지원하지 않는다.

## 보안 및 수명 검토

숨김 상태는 본문과 함께 암호화한다. 파일 경로는 GUID에서만 만들고 기존 파일 크기·RTF·루트/대상 재분석 지점 검사를 유지한다. 목록은 RTF나 본문을 표시하지 않으며 숨긴 메모의 편집기를 보관하지 않는다. 복호화·파일 읽기는 작업 스레드에서, RTF 검사는 UI 디스패처에서 수행한다. 메모 수명 작업은 중복 실행을 막는다.

NoteSession은 표면 이벤트·저장 타이머·편집기·창을 정리한다. 목록 창은 닫을 때 작업공간 이벤트 구독을 해제한다. TrayController는 종료 시 트레이·메뉴·복제한 아이콘·목록을 폐기한다. Windows 종료·로그오프 요청은 먼저 취소하고 저장 후 앱 종료를 시도하므로 실제 로그오프·절전 동작 검토는 남아 있다.

트레이는 추가 NuGet 패키지 없이 Windows Desktop 프레임워크의 [NotifyIcon](https://learn.microsoft.com/en-us/dotnet/api/system.windows.forms.notifyicon?view=net-10.0)과 ContextMenuStrip을 사용한다. WPF UI와 혼동되지 않도록 WinForms 자동 using을 제외하고 Forms 별칭으로 호출한다.

## 실제 UI 검토 순서

1. 새 메모 2개 생성 → 서로 다른 한글·굵게·색상·목록 입력 → 위치·크기 변경 → 저장 완료 확인
2. 하나 닫기 → 다른 메모 유지 확인 → 목록에서 숨긴 메모 열기 → 본문·서식·위치·크기 확인
3. 전부 닫기 → 트레이 유지 확인 → 더블클릭으로 목록 열기 → 새 메모 생성
4. 일부 숨김 상태에서 트레이 종료 → 재실행 → 표시/숨김 상태 확인
5. 저장 실패 시 숨김·종료 취소와 재시도 확인
6. Win+D·한글 조합·탐색기 재시작 시 여러 메모와 트레이 복구 확인

실제 UI 검토, 여러 모니터·혼합 배율, 로그오프·절전 복귀, 8시간/24시간 상주와 실제 GDI·USER 핸들 측정은 아직 수행하지 않았다. 휴지통·로그인 자동 실행·업데이트는 후속 작업이다.

# 연결 복구 및 위치 처리 검증

날짜: 2026-10-13. 작업: WM-003. 버전: 0.2.0. 첫 커밋 37031d9 이후의 로컬 변경이며 GitHub 푸시는 사용자 요청으로 미뤘다.

## 변경 내용

- 2초 간격으로 앱이 소유한 메모 표면과 부모 연결을 확인한다.
- 별도의 숨겨진 알림용 창으로 탐색기 재생성·디스플레이·DPI·전원 관련 변경을 처리한다.
- 부모 창이 사라지면 기존 본문·서식 편집기를 임시 일반 창에 옮겨 보존한다. 이 창은 바탕화면 고정 성공 상태로 표시하지 않는다.
- 연결 대상을 재탐색하고 최대 10회 자동 재시도한다. 실패 후 자동 반복은 중단하며 다시 연결 버튼으로 재시도할 수 있다.
- 새 표면을 만들 때 같은 편집기를 사용하고 이전 훅·창·참조를 해제한다. 메시지를 여러 번 받아도 작업을 합쳐 중복 처리하지 않는다.
- 모니터 작업 영역과 바탕화면 부모의 클라이언트 영역을 교차하여 위치·크기를 제한한다. 음수 화면 좌표를 허용하고 DPI가 바뀔 때 크기를 조정한다.
- 배율·모니터가 달라져도 어떤 Windows 환경에서나 동일하게 동작한다고 주장하지 않는다. 혼합 배율에서 실제 WPF 자식 창의 크기·IME 처리는 별도 검증 대상이다.

## 실행 환경과 결과

기존 Windows 빌드 26200.9457, x64, SDK 10.0.401 및 Windows Desktop 10.0.12를 사용했다.

- Release 빌드: 경고 0, 오류 0
- 기존 9개 검증과 신규 9개 검증: 통과
- 실제 탐색기 바탕화면 표면 생성·해제 1개: 통과
- 복구 구현의 초기 빌드에서 총 19개 검증 통과. 실제 탐색기는 재시작하지 않았다.
- 이후 HWND 소유 프로세스 확인을 강화한 최종 빌드는 컴파일에 성공했으나 아래 앱 제어 정책 차단으로 실행 검증하지 못했다. 최초 19개 결과를 최종 파일의 실행 결과로 취급하지 않는다.

## 최종 실행 차단

최종 Release 빌드: 경고 0, 오류 0. 실행은 FileLoadException 및 0x800711C7로 차단됐다. 일반 승인 환경에서 다시 빌드하고 실행해도 같은 결과였다.

Windows CodeIntegrity 이벤트 3077 및 3033에서 테스트 경로의 WindowsMemo.dll이 Enterprise signing level requirements를 만족하지 못하거나 코드 무결성 정책을 위반했다는 메시지를 확인했다. 적용 정책 ID는 `{0283ac0f-fff1-49ae-ada1-8a933130cad6}`이다. 이 정보만으로 Smart App Control인지 조직용 정책인지 단정하지 않는다.

보안 설정, 서명 정책, 백신 예외를 변경하지 않았다. 승인된 개발 환경 또는 적절한 서명·허용 정책이 마련된 뒤 최종 파일의 19개 검증 및 실제 동작을 다시 확인해야 한다.

| 신규 검증 | 확인한 내용 |
| --- | --- |
| 음수 모니터 좌표 | 왼쪽·위쪽 모니터의 작업 영역 경계 유지 |
| 모니터 제거에 해당하는 위치 | 남은 화면 밖 메모를 영역 안으로 이동 |
| 작은 영역 | 최소 크기보다 작은 화면에서도 표시 범위 안으로 제한 |
| DPI 변환 | 100% → 200% → 100% 크기 왕복 및 화면 위치 유지 |
| 잘못된 배율 | NaN 등 유효하지 않은 배율 거부 |
| 부모 창 손실 | 가짜 부모 창 폐기 후 본문 RTF·서식이 동일한 상태로 새 부모에 재부착 |
| 재시도 제한 | 30회 점검 호출에도 탐색이 10회에서 멈추고 수동 재시도로 복구 |
| 반복 복구 | 가짜 부모 표면 20회 교체 후 원래 본문 유지 |
| 참조 정리 | 타이머·알림용 창이 있는 호스트 및 편집기가 폐기 후 수집 가능 |

가짜 부모 창은 테스트 프로그램이 직접 생성하고 폐기했다. 탐색기 창을 파괴하거나 테스트를 위해 실제 시스템 화면 구성을 변경하지 않았다. 이 시험은 실제 탐색기 재시작의 대체가 아니다.

## 남은 수동 확인

- 정상 부착 상태에서 기존 Win+D·한글·서식 동작의 회귀 확인
- 실제 탐색기 재시작 후 임시 창과 재부착, 입력·서식·창 복원 확인
- 배율 변경·모니터 이동·연결 해제와 절전 복귀 확인
- 실제로 보이는 임시 창의 닫기·종료 취소와 수동 재연결 버튼
- 장시간 상주 및 네이티브 핸들 추세

탐색기 재시작과 모니터 변경은 사용자의 작업 환경에 영향을 주므로 시점을 조율한 후 수동 검증한다. 필수 실제 환경 조건이 남아 있어 WM-003은 Done이 아닌 Review 상태다.

## 후속 재검증: 0.3.0

2026-10-13 저장 구현 이후 소유권 확인을 포함한 기존 복구 시험과 실제 바탕화면 호스트 생성·해제를 다시 실행했다. 전체 27개 검증이 통과했고 보안 설정은 변경하지 않았다. 상세는 [저장·복원 검증](STORAGE-03.md)을 따른다. 이 결과는 실제 탐색기 재시작·모니터 시험 완료를 의미하지 않는다.

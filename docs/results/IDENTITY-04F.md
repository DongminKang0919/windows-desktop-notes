# WM-004F — 재실행 후 중복 복구 방지

2026-10-22, 0.9.7 prototype, SDK 10.0.401. PR #7 병합본 6971904에서 분리했다. 기존 WPF·WinForms 트레이·DPAPI·저장 경로·스키마 4와 일반 메모 ID를 유지한다.

## 동작

선택한 임시 파일을 지문·스키마·RTF로 재검증한 뒤 **파일 토큰과 암호화 파일 SHA256 지문**에서 복구 사본 ID를 일정하게 계산한다. 새 사본의 ID 자체가 저장되므로 별도 영수증 파일·데이터베이스·평문 이력을 추가하지 않는다. 메모 저장과 별도 이력 저장 사이의 중단 구간도 없다. 같은 ID를 이미 발견했으면 새 파일을 쓰지 않고 기존 사본을 안내한다.

살아 있는 편집기는 현재 내용을 유지하며 숨김·보관함·휴지통의 사본은 기존 파일을 읽어 상태를 확인한다. 기존 편집·백업·색상·보관·삭제 상태를 원본 스냅샷으로 되돌리지 않는다. 손상되거나 사라진 사본을 찾았다고 조용히 다시 쓰지 않는다. 백업만 있는 사본도 인식하며 이 경로에서 본체를 복구 저장하지 않는다.

새 사본은 `SaveNew`로 생성한다. 기존 본체 또는 백업이 있으면 거부하고, 검사 이후 다른 저장 요청이 본체를 만든 경우도 최종 파일 이동에서 덮어쓰지 않는다. 기존 `Save`의 편집·백업 교체 동작은 유지한다. 임시 원본·기존 메모는 보존한다. 재실행 간 메모리 사전은 제거했다.

### 식별자 계약

- 정규 입력은 ASCII `WindowsMemo.PendingCopy.v1:{토큰 N 형식}:{대문자 64자리 지문}`이다. SHA256의 앞 16바이트에 version 8/variant 비트를 설정하고 big-endian GUID로 해석한다. 지문은 사용자 입력이 아니라 다시 읽은 파일에서 얻는다.
- 이 v1 계산 규칙은 후속 버전에서 바꾸지 않는다. 토큰 `11111111-2222-4333-8444-555555555555`와 A 64자리 지문의 고정 벡터는 `1966fac2-d98d-8de1-8799-78f9d628e442`다. 이 검사는 버전 변경으로 중복 방지가 조용히 깨지는 일을 막는다.
- 식별자는 기존 파일을 덮어쓸 권한이나 게시자 인증 수단이 아니다. 충돌/경합/손상 시에도 기존 파일을 보존하는 경로를 적용한다. 같은 사용자 계정의 악성 프로세스에 대한 완전한 격리를 보장하지 않는다.

## 범위와 제한

0.9.7부터 새로 만든 복구 사본에 적용한다. 이전 버전의 무작위 ID와 원본을 연결할 정보가 없어 자동 추정·병합하지 않는다. 같은 본문이어도 파일 이름이나 암호문이 달라지면 별도 스냅샷이다. 영구 삭제 후 사용자가 명시적으로 다시 복구하면 같은 복구 ID로 새 사본을 만들 수 있다. 임시 원본을 자동 승격·삭제하지 않으며 전체 보존 기간 정책은 여전히 후속이다.

## 검증

- Release 빌드 경고·오류 0. 로컬 **111개 PASS**(자동 110개 + 실제 비표시 바탕화면 호스트 1개).
- 고정 벡터·지문 대소문자·다른 토큰/지문 구분과 잘못된 입력 거부를 확인했다.
- 새 파일 저장에서 본체·백업·백업만 있는 상태를 보존하고, flush 뒤 경합 저장을 주입하여 최종 생성이 원본을 교체하지 않는지 확인했다.
- 사본을 편집·숨김한 뒤 작업공간을 폐기·재생성하여 ID·메모 수·본체/백업 바이트 불변을 확인했다. 보관함·휴지통 상태와 백업만 있는 사본도 유지한다. 손상/사라진 사본 거부, 변경 원본의 새 ID, 영구 삭제 후 명시적 재복구를 검증했다.
- UI의 반복 복구 안내와 창 20회 열기/닫기·목록 탐색 검사를 유지한다. 장시간 메모리·핸들 누수 부재를 보장하지 않는다.
- 강제 종료 **10건 PASS**: 기존 저장 경계 8건과 사본의 TemporaryFlushed/Committed 2건. 새 두 경우는 각각 별도 읽기 프로세스 2개에서 실제 작업공간 복구를 실행하여 같은 ID 재사용·중복 없음·기존 파일 불변·임시 원본 보존을 확인했다. 종료는 직접 만든 시험 자식만 대상으로 한다.
- JSONL: `artifacts/recovery-identity-validation/bin/WindowsMemo.Tests/release/crash-probe/c9878d905c5c42728e22ccc6ee9d2188/results.jsonl`. 마지막 기록의 passed=8은 기존 시나리오 수, identityRecovery=2는 신규 중복 방지 시나리오 수다.
- README 흐름도를 새 사본/기존 사본 분기로 갱신했다. 복구 화면 PNG도 0.9.7 로컬 시험 데이터로 렌더하고 직접 열어 한글·안내·버튼·본문의 표시를 확인했다. SHA256은 `83fa1b754058dfe14a666e86aa48c9c0d9a89369828ce1c0a678badf55dc43b1`이다. 실제 바탕화면 캡처와 구분하며 [이미지 안내](../images/README.md)를 따른다.

```powershell
dotnet build WindowsMemo.slnx --configuration Release -p:RestoreLockedMode=true --artifacts-path artifacts/recovery-identity-validation
dotnet artifacts/recovery-identity-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll --shell-probe
dotnet artifacts/recovery-identity-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll --crash-probe
```

모든 데이터는 빌드 출력 아래 GUID별 시험 폴더에 만들었다. 사용자 메모·탐색기·실행 중 사용자 앱·시스템 설정을 변경하지 않았다. 실제 Win+D·IME·혼합 DPI·보이는 창·장치 장애/전원 차단·링크/정션 조합·설치본·8/24시간 상주는 별도 수동 확인이다.

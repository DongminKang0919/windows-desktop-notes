# 0.5.0 휴지통·복원 검증

- 날짜: 2026-10-13
- 작업: WM-008 및 관련 저장 보호·수명 검토
- 상태: Review — 구현·자동 검증 완료, 실제 UI 검토 대기
- 환경: Windows 빌드 26200.9457 / x64, .NET SDK 10.0.401

## 사용자 동작

메모의 휴지통으로 이동 버튼 또는 일반 목록에서 휴지통으로 이동을 선택한다. 표시 중인 메모는 최신 스냅샷과 삭제 상태를 함께 저장한 뒤 창·편집기·자동 저장 서비스를 폐기한다. 숨긴 메모는 파일에서 최신 레코드를 읽어 삭제 상태로 저장한다. 실패하면 원래 목록과 최신 편집기를 유지한다.

트레이의 휴지통 메뉴는 삭제된 항목만 표시한다. 복원은 삭제 상태를 해제하고 숨김 상태로 일반 목록에 돌려놓는다. 복원 실패는 휴지통 항목을 유지한다. 휴지통은 자동으로 비우지 않는다. 영구 삭제는 휴지통 화면의 확인 대화상자에서 예를 눌렀을 때만 수행하며 기본 선택은 아니오다.

## 저장과 영구 삭제

스키마 3의 DeletedAtUtc를 본문·Hidden 상태와 함께 DPAPI CurrentUser로 보호한다. 삭제 시 Hidden=true이며 삭제 시각은 생성·수정 시각 사이여야 한다. 기존 스키마 1·2는 삭제 시각 없이 읽는다. 0.5.0 저장 이후 이전 앱 버전으로 되돌리는 데이터 호환성은 지원하지 않는다.

영구 삭제는 저장소에서 휴지통 상태를 다시 검증한다. 백업만 남거나 손상 원본에서 백업으로 복구한 경우에는 정상 휴지통 본체를 먼저 저장한다. 이후 해당 ID의 정상 백업과 GUID 이름의 손상 보존본을 먼저 삭제하고 본체는 마지막에 삭제한다. 중간 실패·중단에서 이전 정상 백업이 일반 메모로 자동 복원되는 경로를 줄이고, 남은 휴지통 본체로 재실행·재시도할 수 있다. 일부 보관본 삭제 후 실패할 수 있어 영구 삭제 전체를 원자적·되돌릴 수 있는 작업으로 약속하지 않는다.

삭제 경로는 검증된 GUID에서만 생성한다. 루트 조상·본체·백업·삭제 대상 손상 보존본의 재분석 지점을 거부하며 다른 메모 파일과 잘못된 보존 파일명은 삭제하지 않는다. 임의의 경로 입력이나 데이터 루트 재귀 삭제는 사용하지 않는다. 예전 비정상 종료로 남은 식별 불가능한 임시 파일은 다른 메모 파일을 잘못 지우지 않도록 이 작업에서 삭제하지 않는다. 영구 삭제는 파일 제거이며 보안 삭제나 포렌식 흔적 제거가 아니다.

모든 메모를 지운 뒤 다음 시작에서 만든 빈 메모는 새 GUID를 사용한다. 이전 버전의 고정 ID 파일 복원은 유지한다.

## 남은 검토

실제 앱에서 표시·숨김 메모 각각 휴지통 이동 → 트레이 휴지통 → 복원 → 일반 목록에서 열기 → 서식·위치 확인을 수행한다. 영구 삭제 대화상자의 아니오·닫기 취소, 예 승인, 다른 메모 유지 및 재실행을 확인한다. 실제 쓰기/삭제 권한 오류, 재분석 지점 공격, 전원 중단, Win+D·IME 회귀·다중 모니터·장시간 상주·USER/GDI 핸들 측정은 미검증이다.

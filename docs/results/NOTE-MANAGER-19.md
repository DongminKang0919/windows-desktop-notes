# WM-019: 찾기·정리·실수 복구를 한 화면에서

2026-11-19 · 0.12.0 prototype · 제품 고도화 로드맵 첫 개발 단위.

## 사용자 흐름

- 메모 목록·보관함·휴지통을 한 관리 창의 탭으로 통합했다. 트레이와 메모에서 각각 요청해도 같은 창의 해당 탭으로 이동한다.
- 제목 일부를 입력해 검색한다. 직접 제목이 없으면 기존 본문 첫 줄 요약을 검색한다. 앞뒤 공백과 대소문자를 무시하며 본문 전체 검색은 포함하지 않는다.
- 메모 목록에서 전체 상태·표시 중·숨김·처리 실패로 필터링한다. 보관함과 휴지통에서는 제목 검색만 적용한다. 탭을 오갈 때 검색어와 메모 목록의 필터를 유지하며 각 탭의 선택을 기억한다.
- Ctrl+F로 검색창에 이동하고, Escape 또는 지우기 버튼으로 검색을 지운다. 검색창의 아래쪽 방향키로 첫 결과를 선택한 뒤 Enter로 열기/복원할 수 있다.
- 메모가 없는 상태와 검색 결과가 없는 상태를 구분하고 검색 결과 개수와 전체 개수를 표시한다. 편집 중 제목이 바뀌면 검색 결과에도 반영한다.
- 삭제 성공 안내와 트레이에 **삭제 실행 취소**를 제공한다. 현재 실행에서 가장 최근에 성공한 휴지통 이동 1건을 되돌린다. 보관함에서 삭제했으면 보관함으로, 일반 메모는 숨김 상태로 목록에 돌려놓고 선택한다. 영구 삭제와 재실행 이후에는 실행 취소가 적용되지 않는다.
- 휴지통/보관함에서 복원하면 **복원한 메모 열기**를 제공한다. 검색·필터를 지워 해당 메모를 선택하고 바로 연다. 열기에 실패하면 목록에 복원된 메모를 유지하며 다시 시도할 수 있다.
- 파일 작업 중에는 탭과 작업 버튼을 비활성화한다. 조회/검색은 작업공간의 메모리 제목만 사용하며 새 평문 인덱스나 편집기를 만들지 않는다. 저장 스키마 5와 DPAPI 방식은 유지한다.

## 검증

- SDK 10.0.401, Release 빌드 경고·오류 0.
- 전체 회귀 **167개 PASS**. 그 뒤 안내 문구와 렌더 타이밍을 정리하고 메모 관리 전용 검사 **11개 PASS**를 다시 확인했다.
- 새 검사는 잠긴 파일에서도 추가 읽기/쓰기 없이 제목 검색·상태 필터·탭 선택 유지가 동작하는지, 제목 변경이 검색에 반영되는지 확인했다.
- 삭제 취소 실패의 파일/취소 대상 보존, 잠금 해제 후 재시도, 보관함 복귀, 최근 삭제 대상 교체, 재실행 후 상태 보존을 확인했다.
- 복원 후 다른 검색어가 남아 있어도 해당 메모를 찾아 여는 흐름과 작업 중 탭 전환 차단을 확인했다. 기존 복원 실패/재시도·선택 유지·닫힘 후 참조 회수도 통과했다.
- 합성 데이터의 검색 중/결과 없음/삭제 취소/복원 후 열기, 탭·선택·최소 크기·오류 안내 화면을 렌더하고 육안 확인했다. 최소 창 높이는 검색·탭 공간을 고려해 520 DIP로 조정했다.
- 실제 사용자 클릭·IME 검색 입력·Ctrl+F/방향키와 Windows 배율 전환은 별도 검토 대상이다. 사용자 메모를 삭제·복원하거나 실행 중인 구버전을 종료하지 않았다.
- 기본 실행 경로 빌드는 실행 중인 WindowsMemo의 EXE 잠금으로 MSB3027/MSB3021에서 중단됐다. 별도 artifacts 빌드·검사는 성공했으며 코드 컴파일 실패와 구분한다. 실행 중 앱을 저장 후 종료하고 루트 실행 파일로 다시 빌드해야 새 버전이 적용된다.

## 재현

```powershell
dotnet build WindowsMemo.slnx -c Release -p:RestoreLockedMode=true --artifacts-path artifacts/note-manager-validation
dotnet artifacts/note-manager-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll
dotnet artifacts/note-manager-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll --note-list-only
```

로그는 `artifacts/note-manager-validation/regression.log`, `note-manager.log`, 화면은 테스트 출력의 `ui-previews`에 남는다. 기존 앱에서 **모든 메모 저장 후 종료** 후 루트의 **메모 실행.cmd**로 새 버전을 실행한다.

# WM-007E: 트레이 없이 메모 목록에 접근

2026-11-18. PR #18 병합 후 `origin/main`의 `c8651d9`에서 작업했다. 개발 버전은 0.9.17 prototype이다.

## 관찰과 변경

- 사용자 PC에는 SDK 11.0.100만 있어 global.json이 요구하는 SDK 10.0.401을 찾지 못했다. Microsoft 서명이 유효한 공식 설치 프로그램으로 SDK 10.0.401을 추가했고 두 SDK를 함께 유지했다.
- 기존 0.9.16 프로세스는 WPF 메시지 루프에서 정상 대기 중이었지만 사용자는 메모와 트레이 아이콘을 볼 수 없었다. 기존 단일 실행 처리는 재실행을 막고 트레이를 찾으라는 안내만 표시했다.
- 직접 실행하면 초기화 후 일반 메모 목록을 항상 연다. 로그인 자동 실행은 기존처럼 오류가 없으면 목록을 열지 않는다.
- 같은 Windows 세션의 이름 있는 자동 재설정 이벤트로 재실행 요청을 기존 프로세스에 전달한다. 초기화 전 요청도 초기화 후 목록을 연다. 수신은 종료 시 해제하고 UI 작업은 WPF 디스패처에서 처리한다. 메모 파일이나 설정을 전달하지 않는다.
- 사용자 저장 파일을 artifacts 아래에 백업한 후 접근할 수 없는 프로세스를 종료했다. 진단 모드에서 목록 표시를 사용자에게 확인받은 뒤 수정본을 일반 모드로 실행했다. 진단 모드는 별도 저장 공간임을 안내했다.

## 검증

- 수정 전 0.9.16: SDK 복구 후 Release 경고·오류 0, 자동 검사 154개 통과.
- 수정 후 별도 artifacts 빌드: Release 경고·오류 0, 자동 검사 155개 통과. 신규 검사는 초기화 전 이벤트 보존, 반복 전달, 수신 해제와 반복 폐기를 확인한다.
- 실제 수정본 일반 실행: 원래 저장 공간의 메모 1개를 보여 주는 메모 목록 창을 확인했다.
- EXE 재실행: 두 번째 프로세스가 코드 0으로 종료되고 기존 프로세스 1개만 유지됨을 확인했다.
- 샌드박스에서는 NuGet.Config 접근과 DPAPI 사용이 제한되어 빌드·검사를 승인된 사용자 권한으로 수행했다.

## 남은 확인

목록 접근 복구와 바탕화면에 붙은 편집기의 실제 가시성은 구분한다. 현재 Windows 셸에서 바탕화면 메모가 보이지 않는 사용자 보고의 원인은 확정되지 않았으며 실제 Win+D·한글 입력·트레이·모니터 환경 검증이 남아 있다. 코드 서명·설치본 업데이트·장시간 상주 검증도 이번 변경의 완료 범위가 아니다.

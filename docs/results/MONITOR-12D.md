# WM-012D: 실제 사용 프로세스 감시와 데스크톱 시험 묶음

2026-11-18. 노트북에서 개발하고 데스크톱에서 장시간 시험하기 위해 별도 수집기를 추가했다. 앱 동작·메모 저장 형식은 변경하지 않았으며 앱 버전 0.9.18을 유지한다.

## 구성

- `tools/WindowsMemo.Monitor`: net10.0-windows 콘솔 도구. 새 외부 패키지 없이 프로세스 자원 API와 Win32 GUI 자원·WM_NULL 응답 참고값을 사용한다.
- `--exe`의 절대 경로가 일치하는 프로세스를 수집하고 PID와 시작 시각으로 실행 구간을 구분한다. 고정 `--pid` 모드는 해당 프로세스 종료 시 끝낸다. 일반 모드는 앱을 직접 다시 실행했을 때 같은 경로의 새 프로세스를 추적한다.
- 기본 10초, 최대 168시간/100,000표본. JSONL은 각 줄마다 flush하고, CSV·환경 조건·이벤트와 5분 주기/정상 종료 시 HTML·JSON 요약을 생성한다. Q/Ctrl+C는 수집기만 종료한다.
- CPU는 프로세스 CPU 시간 증가분을 monotonic 경과 시간과 논리 CPU 수로 나눈다. 긴 표본 공백은 CPU에서 제외하고 별도 기록한다. 사용/유휴 전환 시 CPU 기준을 재설정한다.
- 5분 워밍업과 충분한 표본을 확보한 경우에만 추세를 계산한다. 프로세스 재시작 전후를 합치지 않는다. 보고서는 누수·안정성 합격 판정을 하지 않는다.
- 원본 JSONL에서 보고서를 재생성할 수 있고 불완전한 줄은 제외 개수를 알리며 원본을 유지한다. 이벤트는 HTML escape한다.
- 노트 내용·제목·파일·화면·키 입력·클립보드·덤프를 수집하거나 전송하지 않는다. 실행 경로에는 사용자 이름이 포함될 수 있음을 안내한다.

## 배포와 검증

- `scripts/package-desktop-test.ps1` 실행: 격리 Release 빌드 경고·오류 0, 메모 자동 검사 156개, 감시기 self-test 통과 후 앱과 도구를 각각 Windows x64 self-contained로 publish했다. .NET 10.0.15 런타임이 두 구성요소에 포함됨을 runtimeconfig와 실제 파일로 확인했다.
- 도구 self-test: 초기 스파이크를 제외한 선형 추세, 구간 CPU·전체 CPU 정규화·공백/초기 기준 제외, 짧은 기록의 추세 미계산, PID 재사용 분리, 불완전 JSONL 복구, HTML escape, CSV 필드, 비유한 인수 거부.
- 실제 앱 PID 28212를 15초 및 런타임 포함 도구로 12초 관찰했다. CPU·메모리·핸들·GDI/USER·UI 응답 값과 종료 시 보고서를 확인했다. 앱을 종료하거나 데이터를 변경하지 않았다.
- 5초 뒤 정상 종료하는 별도 PowerShell 시험 프로세스: 6표본, process_exited/exitCode 0, fixed_process_exited 종료 및 보고서 생성 확인. 초기 도구 실행 준비 오류와 셸 경로 차이를 바로잡은 뒤 최종 시험을 통과했다.
- 다른 경로의 메모가 실행 중일 때 --launch: 새 앱을 띄우지 않고 other_path_running으로 안내, 오류 종료 및 세션 기록을 남기는 것을 확인했다.
- 합성 HTML 보고서를 별도 headless Edge 프로필에서 렌더링하고 한글·요약·그래프 표시를 확인했다.
- ZIP의 앱·도구·8/24시간 CMD·안내·런타임과 667개 파일의 크기·SHA256 및 ZIP 체크섬을 검증했다. 메모·logs·self-test 폴더가 포함되지 않음을 확인했다.
- Windows CI에는 감시기 self-test를 연결했다. 이번 변경의 원격 CI는 아직 실행하지 않았다.

## 범위의 한계

실제 데스크톱의 8/24시간 시험은 대기 중이다. 종료 코드만으로 크래시 원인·강제 종료 여부를 확정하지 않고 UI 참고 응답만으로 입력·렌더·저장 성공을 판단하지 않는다. GC 힙·참조 경로·앱 내부 예외 스택은 수집하지 않는다. 실제 추세나 문제 시각을 찾은 뒤 추가 진단할 기반을 준비한 것이다. 로그아웃/재부팅은 감시도 종료하므로 재로그인 후 새 세션을 시작해야 한다.

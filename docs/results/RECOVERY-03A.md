# WM-003A — 복구 중단 후 셸·절전 복귀 알림 처리

- 날짜: 2026-10-22, 0.9.2 prototype, 저장 스키마 4 유지.
- 기준: 최신 origin/main 6e6d01a(PR #2 squash 병합)에서 독립 브랜치를 시작했다.

## 문제와 변경

기존 구현은 2초 간격 복구가 10회 실패하면 타이머를 멈췄다. 이후 `TaskbarCreated`나 절전 복귀가 와도 `RecoveryStopped` 조건 때문에 검사 자체를 건너뛰어 수동 재연결이 필요했다. 알림을 큐에 넣는 기존 구조를 유지하면서 셸 생성 또는 절전 복귀(자동 0x12 / 사용자 7)를 받으면 소진된 재시도 한도를 재설정한다. 새 시도도 최대 10회로 제한한다.

일반 설정·디스플레이·배터리 상태 알림은 중단된 재시도를 재개하지 않는다. 이미 재시도 중이면 새 알림이 한도를 초기화하지 않는다. 대기 중인 일반 레이아웃 검사 뒤에 들어온 복구 신호도 보존하며, 한 dispatcher 작업으로 합친다. 폐기 후 대기 콜백은 창/타이머를 되살리지 않는다. 절전 복귀 메시지를 처리하면 TRUE를 반환하며 외부 메시지의 lParam 포인터를 읽지 않는다.

기존 편집기 객체를 임시 창에서 바탕화면 자식 HWND로 옮기는 방식, TopMost 미사용, 데이터 경로·DPAPI·메모 저장 방식은 유지한다. 외부 프로세스 종료나 시스템 설정 변경은 없다.

## 검증

- Windows x64 26300 / SDK 10.0.401, 최초 Release 빌드 경고/오류 0.
- 수정 전 추가 회귀 시험에서 중단 후 TaskbarCreated를 받아도 재시작하지 않는 문제를 재현했다.
- 추가 시험 2개는 이 프로세스의 비표시 observer HWND에만 SendMessage를 보내며 시스템 전체에 방송하지 않는다. 대기 알림 병합, 새 시도의 상한, 진행 중 한도 보존, 복구 후 한글 본문·굵기·글자색·종이색·접힘·좌표 보존과 폐기 후 콜백 무효화를 확인한다.
- 로컬 최종 실행은 Windows 애플리케이션 제어가 시험 DLL 로드를 차단했다(0x800711C7, 동일 실행 재확인도 차단). 정책 비활성화·파일 차단 우회는 수행하지 않았다. 최종 회귀 검증은 GitHub Windows CI로 확인하며 결과를 PR에 기록한다.

## 실제 환경에서 남은 확인

이 시험은 실제 Explorer 종료·재시작이나 PC 절전을 수행하지 않는다. 실제 탐색기 준비 지연 후 재부착, 절전/최대 절전 복귀, Win+D·IME 입력, 혼합 DPI·모니터 제거와 8/24시간 상주 시험은 별도 수동 검증이다. 알림 주입 통과를 해당 작업의 실환경 검증 완료로 표시하지 않는다.

근거: Microsoft의 [TaskbarCreated 알림](https://learn.microsoft.com/en-us/windows/win32/shell/taskbar#taskbar-creation-notification)과 [WM_POWERBROADCAST 이벤트·반환값](https://learn.microsoft.com/en-us/windows/win32/power/wm-powerbroadcast)을 확인했다.

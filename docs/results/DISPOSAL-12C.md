# WM-012C: 비동기 작업과 소유자 폐기 경합

2026-10-22. PR #13 병합 후 main `2378824` / 0.9.11을 확인하고 독립 브랜치에서 0.9.12로 수정했다. 기존 작업 트리는 깨끗했고 사용자 변경은 없었다.

## 문제와 수정

`ShowAsync`는 숨긴 메모를 읽은 뒤 `Open`을 호출한다. 읽기 대기 중 `NoteWorkspace.Dispose`가 실행되면 기존 세션과 목록은 정리되지만, 늦은 완료가 새 편집기·표면·자동 저장 타이머를 생성할 수 있었다. 숨긴 메모의 보관·휴지통·복원도 읽기 후 소유자 폐기 확인 없이 후속 저장을 시작했다. `NoteSession.CloseAsync`는 저장 대기 중 폐기된 경우에도 실패 안내로 편집기 상태를 바꿀 수 있었다.

- 작업공간의 읽기·저장 대기 후 폐기를 확인한다. 폐기된 작업공간은 새 창이나 다음 저장을 시작하지 않고 `false`를 반환한다.
- 이미 시작한 원자적 파일 저장·명시적으로 확인된 영구 삭제는 강제 중단하지 않는다. 완료 후 폐기된 목록을 변경하거나 알림을 발행하지 않는다. 따라서 `false`는 저장소 롤백을 뜻하지 않는다. 다음 실행은 저장소의 실제 상태를 읽는다.
- 전체 저장은 폐기 후 다음 세션 저장과 종료 인계 콜백을 호출하지 않는다. 편집기 재활성화도 하지 않는다.
- 메모 세션은 저장 완료/실패 이후 폐기를 먼저 확인한다. 폐기된 오류 UI를 갱신하거나 자동 저장 재시도를 예약하지 않는다.
- 기존 `InitializeAsync`, 복구 사본의 원자적 저장 및 고정 ID 정책은 유지한다. 이미 시작한 복구 사본 저장은 완료될 수 있지만 폐기 후 작업공간에 등록하지 않는다.

새 프레임워크·백그라운드 루프·동기 대기·메시지 펌프를 제품 코드에 추가하지 않았다. DPAPI CurrentUser, 스키마 4 및 기존 호환성, 원본·백업·미완료 파일 보호와 바탕화면 부착/TopMost 구분은 변경하지 않았다.

## 회귀 검사

실행형 하네스 `WorkspaceDisposalTests`에 네 검사를 추가했다.

1. 숨긴 메모 재열기를 시작하고 UI 완료가 실행되기 전에 작업공간 폐기: 결과 실패, 새 표면 0, 파일 해시·수정 시각·파일 집합 불변.
2. 숨긴 메모의 보관·휴지통·보관 복원·휴지통 복원 네 경로에서 읽기 대기 중 폐기: 후속 저장 없음, 새 표면 및 뒤늦은 변경 알림 0, 파일 불변.
3. 저장 확정 뒤 종료 인계 콜백에서 작업공간 자체를 폐기: 표면 정리, 뒤이은 인계/열기/삭제 요청 거부.
4. 메모 세션의 숨김·보관·휴지통 각각에 실제 저장 경계(`TemporaryFlushed`) 게이트를 두고 진행 중 폐기: 성공/합성 I/O 실패 여섯 경로에서 UI 상태 불변, 세션 폐기 유지, 추가 Flush 거부. 성공 시 저장 파일의 숨김·보관·삭제 표시를 재검증한다.

테스트의 Dispatcher 펌프와 파일 저장 게이트는 시간 제한이 있으며 제품 경로에는 없다. 시험 파일은 빌드 출력 아래 GUID별 `workspace-disposal-tests`에만 만든다. 실제 사용자 메모는 읽거나 수정하지 않는다.

## 남은 확인

실제 표시된 창과 느린 디스크, Windows 종료/취소·재시도 및 앱 폐기 경합은 수동 확인이 필요하다. 사용자의 PC 로그아웃·재부팅·Explorer 재시작이나 실행 중 앱 종료는 수행하지 않았다. 게시자 인증·서명·실제 설치본 업데이트와 8/24시간 전체 앱 상주는 미완료다. 유한한 자동 검사를 근거로 무누수·무취약점을 보장하지 않는다.

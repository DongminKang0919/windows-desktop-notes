# WM-008A: 메모 목록에서 휴지통 접근·복원

2026-11-19, 0.10.1 prototype.

## 문제와 변경

휴지통 이동과 복원 처리는 기존에 구현되어 있었지만, 휴지통 창은 트레이 메뉴에서만 열 수 있었다. 메모 목록에서 실수로 삭제한 뒤 복원 경로를 찾기 어려웠다.

- 메모 목록 오른쪽 위에 **휴지통** 버튼을 추가했다. 트레이와 같은 휴지통 창을 사용하며 이미 열려 있으면 활성화한다.
- 휴지통·보관함 오른쪽 위에 **메모 목록** 버튼을 추가했다. 휴지통에서 **선택한 메모 복원** 후 목록으로 돌아가 메모를 다시 열 수 있다.
- 목록 안내에 휴지통 복원 경로를 표시했다. 헤더는 제목과 버튼 영역을 나누어 배치했다.
- 복원은 기존과 같이 숨김 상태이며 본문·제목·서식·배치를 보존한다. 저장 스키마와 암호화 방식은 변경하지 않았다. 영구 삭제는 기존 확인 대화상자를 유지한다.
- 새 휴지통 요청 이벤트는 트레이 폐기 시 구독을 해제하고 작업공간 폐기 시 정리한다. 닫힌 목록은 탐색 요청을 보내지 않는다.

## 검증

- SDK 10.0.401, Release 빌드 경고·오류 0. `--artifacts-path artifacts/trash-navigation-validation`, 잠금 복원 사용.
- 자동 검사 **165개 PASS**. 추가 검사는 목록에서 삭제 → 휴지통 요청 → 해당 메모 선택·복원 → 목록 요청 → 새 작업공간으로 재실행·열기를 검증했다. 직접 제목, RTF bytes, 위치·크기, 숨김·삭제 상태 및 닫힘/폐기 이후 요청 억제를 확인했다.
- 기존 복원 실패 후 파일 보존·재시도, 빈 휴지통 버튼 상태, 목록 선택 유지, 최소 창 크기 및 100/150/200% 렌더 검사도 통과했다.
- 생성된 `notes-list-100.png`, `trash-list-100.png`를 눈으로 확인했다. 로컬 로그와 렌더는 위 artifacts 폴더 아래에 보관한다.
- 사용자 메모를 휴지통으로 옮기거나 영구 삭제하지 않았다. 실제 앱에서 이번 버튼을 누르는 수동 검토는 남아 있다.

## 사용

실행 중인 이전 앱을 트레이의 **모든 메모 저장 후 종료**로 닫은 뒤 루트의 **메모 실행.cmd**를 실행한다.

**메모 목록 → 휴지통 → 메모 선택 → 선택한 메모 복원 → 메모 목록 → 선택한 메모 열기**.

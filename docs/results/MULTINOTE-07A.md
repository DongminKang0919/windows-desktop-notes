# WM-007A 여러 메모 저장 기반

- 날짜: 2026-10-13
- 상태: Done — 최초 실행 차단 후 0.4.0 통합 검증에서 저장 기반 검증 완료
- 앱 버전: 0.3.0 개발 단계 유지. 사용자 UI는 여전히 메모 하나다.

## 변경

FileNoteRepository에 메모 ID를 받는 생성자와 Id 속성을 추가했다. 기존 생성자는 0.3.0 고정 ID로 동작하여 기존 파일을 그대로 읽는다. 스키마와 암호화 봉투는 변경하지 않았다. 저장·복원 양쪽에서 내부 ID와 저장소 ID의 일치를 검사한다. AutosaveCoordinator는 저장소의 ID로 스냅샷을 만든다.

DiscoverIds는 저장 루트 바로 아래의 GUID(N).json과 GUID(N).json.bak 이름만 탐색한다. 백업만 남은 메모를 포함하며 ID 중복을 제거하고 정렬한다. 임시·손상 보존 파일과 잘못된 이름은 제외한다. 목록 탐색 중 본문 복호화나 WPF 편집기를 생성하지 않는다. 초기 탐색 한도는 1,000개이며 초과 시 파일을 삭제하거나 일부 목록을 정상 결과로 반환하지 않고 오류로 중단한다.

## 검증

```powershell

dotnet tests/WindowsMemo.Tests/bin/Release/net10.0-windows/WindowsMemo.Tests.dll
```

- 자동 검증: DLL 로드 단계 실패, 종료 코드 1. 새 검증을 통과로 표시하지 않는다.
- 차단: WindowsMemo.dll 로드 시 0x800711C7. CodeIntegrity/Operational의 3077·3033 이벤트에서 서명 수준 요건 위반을 확인했다.
- git diff --check: 통과
- 추가한 검증 4개: 독립 저장·백업·손상 복구와 기존 ID 호환, 목록 중복·백업만 남은 메모 탐색, 잘못된 ID 저장·교체 거부, 두 메모 동시 자동 저장의 본문·ID·위치 분리
- 기존 26개 + 신규 4개로 기본 실행 시 30개를 기대하지만 실제 실행 성공은 미확인이다. 기존 26개 통과 기록은 변경 전 CI 작업의 결과다.

## 보호 및 리소스 검토

저장 경로는 형식화한 GUID로만 생성한다. 루트 조상과 대상 본체·백업의 재분석 지점 검사는 유지했고 ID 탐색에도 적용했다. 메모별 암호화·원자 교체·백업 복구는 기존 경로를 사용한다. 추가한 목록은 최대 1,000개 ID만 보관하며 스트림·UI·타이머를 소유하지 않는다. 새 자동 저장 테스트는 두 편집기와 두 서비스 모두 Dispose한다. 같은 계정의 경로 변경 경쟁 조건과 실제 재분석 지점 공격 시험은 이번에 검증하지 않았다.

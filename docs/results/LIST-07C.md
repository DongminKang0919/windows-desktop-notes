# WM-007C — 첫 줄 제목으로 구분하는 목록

2026-10-22, 0.9.10 prototype. PR #10 병합본 `900585e` 기반이다. WPF·WinForms 트레이·암호화 스키마 4·복구 ID v1·기존 데이터와 삭제/복원 정책을 유지한다.

## 변경

메모 목록·보관함·휴지통이 ID만 보여 주던 흐름을 첫 줄 제목·상태·짧은 ID로 바꾼다. 제목이 같은 메모도 ID로 선택·처리한다. 빈 메모는 ‘메모’, 시작 시 읽지 못한 파일은 ‘확인할 수 없는 메모’와 기존 실패 상태로 표시한다. 파일 오류 때문에 항목이나 데이터를 숨기거나 삭제하지 않는다.

`NoteTitleSummary`는 기존 메모 창의 제목 규칙을 공유한다. 앞뒤 공백·첫 줄·체크리스트 기호를 처리하고 80 UTF-16 단위로 제한하며 surrogate 쌍 중간에서 자르지 않는다. 더 긴 본문을 잘라 저장하는 기능이 아니라 표시용 제목만 만드는 것이다.

제목은 기존 파일 복원 검증에서 얻어 메모리에만 보관한다. 목록 조회에 추가 파일 읽기·복호화·편집기 생성이 없으며 별도 평문 인덱스나 로그도 없다. 숨긴 메모에 전체 문서·본문을 유지하지 않는다. 표시 중에는 첫 줄 제목이 바뀔 때만 목록을 알리고, 본문만 바뀔 때는 추가 알림을 만들지 않는다. 숨김·보관·휴지통 이동 이후와 재실행에도 제목을 표시하며 복구 사본은 기존 편집된 사본의 제목을 유지한다.

화면은 NoteTheme의 맑은 고딕·잉크색·따뜻한 바탕·여백을 공유하고 제목/상태를 두 줄로 표시한다. 항목 개수·빈 상태 안내, 최소 28 DIP 버튼, 긴 제목 말줄임, ID 기준 선택 유지, Enter 열기/복원을 제공한다. 같은 ID 목록은 항목 변경만 반영해 매번 전체 목록을 교체하지 않는다. 불변 항목의 제목/상태/접근성 이름은 OneTime 바인딩으로 읽고 항목 교체 때 갱신한다. 창을 닫으면 작업공간 구독과 ItemsSource·목록 참조를 정리한다. 빈 영역의 더블클릭으로 이전 선택을 여는 동작도 막는다. 영구 삭제는 기존 확인 대화상자를 유지한다.

## 검증 방법과 환경

로컬 Windows x64 10.0.26300 / SDK 10.0.401에서 Release 빌드는 경고·오류 0이다. 새 검증 DLL 실행은 Windows 앱 제어 정책 `0x800711C7`에 차단됐다. 보안 설정·서명·화이트리스트·사용자 앱과 메모 저장소를 변경하지 않고 Windows CI에서 동작을 확인한다. 로컬 비표시 셸 검사까지 통과한 것으로 표시하지 않는다.

새 목록 검사 5개는 실제 WPF 컨트롤과 GUID별 합성 암호화 저장소를 사용한다.

1. 숨김·보관·휴지통의 제목, 빈/긴 제목·이모지 경계, 손상 파일 보존과 편집기 표면 미생성.
2. 표시 중 첫 줄 수정·선택 유지, 본문만 수정할 때 추가 목록 알림 없음, 숨김·재실행 후 제목.
3. 같은 제목 두 메모의 ID별 Enter 열기, 빈 영역 더블클릭 무시, 보관·휴지통 복원.
4. 원본을 독점 잠근 상태에서도 목록 표시·100/150/200% 렌더, 파일 목록·SHA256·수정 시각 불변, 좁은 창과 빈 상태.
5. 새 복구 사본 제목과 재실행 후 편집 사본 재인식, 목록 20회 생성·닫기 후 창 참조 회수.

초기 CI는 첫 제목 기대값 검사에서 실패했다. `Run` 하나에 줄바꿈 문자열을 직접 넣던 시험 데이터를 실제 편집기의 `InsertPlainText`→RTF 저장 경로로 수정했고 해당 검사가 통과했다. 그다음 좁은 크기 검사에서 루트의 22 DIP 여백을 이중 차감한 조건을 보정했다. 실제 사용자 파일을 변경하거나 제목 검사를 제거해 통과시키지 않았다.

## 확인한 결과

커밋 `09b9a19`의 [Windows CI](https://github.com/DongminKang0919/windows-desktop-notes/actions/runs/39756293476) 작업 로그에서 Release 경고·오류 0, 자동 **126개**(기존 121 + 목록 5), 격리 자식 중단 복구 **10건**, 복구 창 수명 smoke(폐기 창·문서 참조 0·원본 보존·최종 저장 재시도 성공), UI 렌더 업로드를 확인했다. 기존 숨김/복원 20회 편집기 참조 검사도 유지한다. 최종 참조 검사에서는 항목 템플릿을 실제 배치·활성화한 목록 20개를 닫고 작업공간이 살아 있는 동안 회수 가능한지 확인한다.

목록·보관함·휴지통의 100/150/200% PNG 9개는 같은 실행의 [sample-ui-renders artifact](https://github.com/DongminKang0919/windows-desktop-notes/actions/runs/39756293476/artifacts/12416217472)에 있다(14일 보관). 다운로드 ZIP 해시: `bccc303fd15b8819181b4d5733c3a67fc1bd50601a1f8df19a91638609d4390e`. 로컬 다운로드 프로세스가 OS 액세스 거부로 생성되지 않아 직접 열어 육안 확인하거나 새 PNG를 저장소에 복사하지 못했다. 렌더 성공·버튼 크기·최소 콘텐츠 영역 자동 확인과 육안 확인을 구분한다. 기존 README 이미지는 출처를 유지한다.

```powershell
dotnet build WindowsMemo.slnx --configuration Release -p:RestoreLockedMode=true --artifacts-path artifacts/readable-list-validation

dotnet artifacts/readable-list-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll
```

실행 가능한 로그인된 개발 환경에서만 `--shell-probe`를 추가한다. CI는 자동 검사·중단 복구·수명 smoke·UI 렌더를 수행하며 목록 렌더는 `ui-previews/{notes,archive,trash}-list-{100,150,200}.png`로 남긴다. 컨트롤 렌더는 실제 바탕화면 캡처가 아니다.

## 남은 확인

실제 표시 창의 입력·한글 조합·키보드 포커스·스크린리더·고대비·혼합 DPI/배율 이동, 수천 항목의 스크롤 체감, Win+D·Explorer/절전 복귀, 설치본과 8/24시간 전체 앱 상주는 별도 확인이 필요하다. 제목은 메모 내용 일부이므로 화면이나 같은 Windows 계정의 다른 프로그램으로부터 보호한다고 주장하지 않는다. 로컬 정책 차단을 앱 코드로 우회하지 않는다.

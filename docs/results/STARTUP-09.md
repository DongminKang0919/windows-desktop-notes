# 0.6.0 로그인 자동 실행 검증

- 날짜: 2026-10-13
- 작업: WM-009
- 상태: Review — 구현·자동 검증 완료, 실제 로그인·UI 검토 대기
- 환경: Windows 빌드 26200.9457 / x64, .NET SDK 10.0.401

## 구현

현재 계정의 HKCU\Software\Microsoft\Windows\CurrentVersion\Run 아래 WindowsMemo 값으로 등록한다. 앱 시작·조회는 읽기만 수행하고 기본값은 꺼짐이다. 트레이의 로그인 시 자동 실행을 클릭해 명시적으로 켜거나 끈다. 켜기는 현재 빌드 위치 등록 확인을 받으며 일반 창 진단에서는 옵션을 비활성화한다.

명령은 현재 앱 디렉터리의 WindowsMemo.exe 절대 경로를 따옴표로 감싼 뒤 --startup만 붙인다. dotnet 호스트 경로를 자동 실행 대상으로 등록하지 않는다. 실행 파일 존재 여부, 절대 경로·파일명, 따옴표·제어 문자, 명령 길이 260자 제한을 검사한다. REG_SZ로 저장해 환경 변수 확장을 요청하지 않는다. 다른 실행 위치의 기존 등록은 상태를 표시하고 해제 후 사용자가 새 경로로 다시 등록하도록 한다. 등록·해제 실패 시 상태를 다시 조회하며 Run 전체나 다른 앱 값을 삭제하지 않는다.

Windows가 로그인 때 Run 명령을 실행하는 방식과 260자 제한은 [Microsoft Run 문서](https://learn.microsoft.com/en-us/windows/win32/setupapi/run-and-runonce-registry-keys)를 기준으로 했다. 체크는 등록 상태이며 Windows 시작 앱 설정·정책의 실행 차단까지 확인한 상태가 아니다. 개발 빌드 폴더를 이동·삭제하면 재등록이 필요하다. 설치·업데이트의 안정적인 실행 위치는 WM-010에서 연결한다.

--startup 실행은 기존 인스턴스가 있을 때 안내창을 띄우지 않는다. 탐색기 바탕화면 표면을 최대 10회·1초 간격으로 기다리고, 준비 대기 중 생성·종료 중복 동작을 차단한다. 숨김 메모는 자동 표시하지 않으며 전부 숨김인 정상 상태에서는 목록도 자동으로 열지 않는다. 수동 실행의 기존 목록 동작은 유지한다. 메모 데이터 스키마는 3을 유지한다.

## 보안·수명 검토

등록 명령은 앱 내부에서 생성한 경로와 고정 인수뿐이며 메모 내용·저장 파일 값을 사용하지 않는다. 관리자 권한이나 시스템 전체 HKLM 등록을 사용하지 않는다. 레지스트리 핸들은 using으로 해제하며 트레이 옵션·메뉴 이벤트는 종료 시 구독 해제한다. 추가 NuGet 의존성·네트워크 요청은 없다.

## 남은 검토

실제 앱의 트레이 등록 확인·취소·해제, 재실행 체크 상태, Windows 시작 앱 설정·정책과의 관계, 실제 로그아웃·로그인 시 실행 및 숨김 복원을 확인해야 한다. 탐색기 준비 지연의 실제 로그인 환경, 진단 모드 화면의 비활성 표시, 실행 폴더 이동 후 재등록도 UI 검토 대기다. 로그인·OS 정책을 변경하거나 실제 자동 실행을 켜는 작업은 이번 테스트에서 수행하지 않았다.

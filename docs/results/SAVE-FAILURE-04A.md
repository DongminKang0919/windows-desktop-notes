# WM-004A — 저장 실패 안내와 임시 창의 닫기·재연결

- 날짜: 2026-10-22, 0.9.3 prototype, Windows x64 26300 / SDK 10.0.401.
- 기준: PR #3이 squash 병합된 최신 origin/main cce1887에서 별도 브랜치로 시작했다. 저장 스키마 4·DPAPI·기존 경로·WPF/트레이 구조는 유지한다.

## 문제와 변경

저장이 실패하면 자동으로 펼쳐 안내를 보여주지만, 이후 사용자가 다시 접으면 Footer에 있는 오류 문구와 재시도 버튼이 함께 숨겨졌다. 추가 회귀 시험으로 기존 코드에서 재현했다.

NoteView가 저장 실패/재시도 안내 상태를 보관하고, 이 상태에서는 접기 요청을 받지 않는다. 더보기의 접기 항목을 비활성화하고 저장 성공 후 접을 수 있다는 툴팁을 제공한다. 상단 더블클릭도 같은 SetCollapsed 경로로 보호한다. 저장 성공 후 접기와 메뉴를 다시 허용한다. 문서 편집·크기 변경·수동 저장 재시도는 유지한다. 저장 실패가 없는 연결 복구 안내에서는 기존 사용자 접기 선택을 유지한다.

새 타이머·파일 형식·외부 통신을 추가하지 않았다. 메뉴 항목 참조는 Dispose에서 해제한다. 실제 닫기·저장 실패의 원본/편집기 보호는 기존 구현을 사용하고 새 통합 시험으로 검증한다.

## 자동 검증

- Release 경고 0 / 오류 0, 전체 79개 PASS(자동 78개 + 로컬 실제 셸 비표시 probe 1개).
- UI 상태: 실패 후 접기 요청을 거부하고 Footer/재시도 버튼과 안내를 유지한다. 접기 메뉴 비활성화, 재시도 중 유지, 성공 후 접기/메뉴 복원을 검증한다.
- 실제 DPAPI 저장소·NoteWorkspace·NoteSession·DesktopNoteHost를 사용했다. 합성 메모를 저장한 뒤 시험 원본 파일을 FileShare.Read로 열어 교체를 실패시켰다.
- 우리 프로세스의 비표시 임시 HWND에만 WM_CLOSE를 보내 실제 Closing → 저장 후 숨김 경로를 실행했다. 실패 후 HWND가 남고 메모는 표시 상태이며 원본 바이트가 그대로 유지됨을 확인했다.
- 실패 뒤 새 본문·굵기·글자색·크기를 변경했다. 전체 저장 후 종료/업데이트 작업에 쓰는 SaveThenAsync의 후속 동작도 실행되지 않았다. 파일 잠금 상태로 바탕화면에 재부착해 같은 최신 편집기·배치와 오류 안내가 보존됨을 확인했다.
- 잠금을 해제한 뒤 저장 성공, 오류 안내 제거, 접기 허용, 숨김·재표시·작업공간 재생성 후 동일 ID·최종 본문·굵기·글자색·종이색·접힘·좌표 복원을 확인했다. 남은 .tmp는 0개였고 종료 시 모든 시험 호스트/임시 창을 해제했다.
- 기존 폐기 호스트/편집기 참조 회수와 복구 알림·저장·보안 회귀 시험도 포함한다. 강제 GC는 시험에만 있다.

```powershell
dotnet build WindowsMemo.slnx --configuration Release --nologo -p:RestoreLockedMode=true --artifacts-path artifacts/save-failure-validation
dotnet artifacts/save-failure-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll --shell-probe
```

실패 유도와 데이터는 빌드 출력 아래 GUID 저장소에만 적용했다. 사용자 메모·사용자 앱·마우스·시스템 설정은 변경하지 않았다. 실제 탐색기는 종료하지 않았다.

## 남은 수동 확인

보이는 창에서 실제 상단 더블클릭·비활성 메뉴 툴팁·닫기/오류 안내의 렌더링, 권한/용량 부족 상황, 실제 Explorer 재시작/절전/로그인, Win+D·한국어 IME·혼합 DPI와 8/24시간 상주는 남아 있다. 파일 공유 잠금 시험을 모든 디스크 장애나 전체 앱 무누수 보증으로 해석하지 않는다.

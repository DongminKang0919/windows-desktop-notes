# WM-007F: 개발 중 실행 파일 위치 고정

2026-11-18. 설정·제목 기능의 0.10.0 브랜치에서 개발용 고정 실행 진입점을 추가했다. 과거 안내에서 매번 검증용 artifacts 폴더의 EXE를 지정해 버전과 위치를 구별하기 어려웠던 문제를 해결한다.

- 프로젝트 최상위 메모 실행.cmd를 더블클릭한다. 앱이 종료되어 있으면 현재 소스를 잠금 복원으로 Release 빌드한 뒤 src/WindowsMemo/bin/Release/net10.0-windows/WindowsMemo.exe를 실행한다. 빌드 실패 시 오래된 파일을 새로 실행하지 않는다.
- 현재 사용자에게 실행 중인 WindowsMemo가 있고 기본 EXE가 있으면 다시 빌드해 파일을 덮어쓰지 않고 기존 목록을 연다. 새 코드 적용은 저장 후 종료·재실행으로 안내한다. 자동 종료나 강제 종료는 하지 않는다.
- --window는 기존 별도 저장 공간의 진단 모드, --build-only는 앱 실행 없이 빌드만 한다. SDK가 PATH에 없으면 Program Files의 기본 dotnet 경로를 확인한다. SDK 버전 정책은 global.json을 따른다.
- 배치 파일은 ASCII 명령/CRLF로 저장하고 .gitattributes로 체크아웃 줄바꿈을 고정한다. scripts/dev.ps1의 Desktop/Window는 이 파일에 연결하고 기존 Test/ShellProbe 경로를 유지한다. 보안 설정이나 PowerShell 실행 정책을 변경하지 않는다.

## 검증

- 메모 실행.cmd --build-only를 공백·한글 파일명 경로에서 직접 실행했다. .NET SDK 10.0.401로 Release 경고·오류 0. 기본 EXE가 0.10.0으로 갱신됨을 확인했다.
- 잘못된 인수는 사용법과 코드 2를 반환하며 빌드·앱 실행으로 진행하지 않는지 확인했다. dev.ps1 구문 검사를 수행했다.
- 이번 검증은 실제 메모를 변환하지 않도록 빌드 전용으로 수행했다. 실행 중 재열기·사용자 더블클릭은 후속 사용 확인 항목이다. 앱 기능 변경이 없어 기존 0.10.0 자동 164개·복구 10개 시나리오를 다시 실행하지 않았다.

친구에게 전달할 설치 EXE와 GitHub Releases 인터넷 업데이트는 이 개발용 실행 파일과 별개다. 배포 방향·남은 검증은 DISTRIBUTION.md에 기록했다.

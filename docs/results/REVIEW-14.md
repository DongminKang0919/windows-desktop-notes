# WM-014 — 0.9.1 prototype 중간 점검·최적화·보안·자원 측정

- 날짜: 2026-10-22
- 기준 소스: f36a047 (0.9.0), 환경 Windows x64 10.0.26300.0 / SDK 10.0.401
- 결과: Release 경고 0 / 오류 0, 전체 71개 PASS. 저장 스키마 4·데이터 경로·DPAPI·바탕화면 자식 창 구조 유지.

## 발견한 문제와 수정

1. 입력 한도 검사와 TextChanged/제목 갱신에서 전체 본문 문자열을 중복 생성했다. 변경 이벤트에서 한 번 읽은 길이와 문자열을 공유한다. 문서 교체·선택 교체 시 길이를 갱신하고 기존 입력 제한을 유지한다. 제목은 Span으로 첫 줄을 찾아 화면용 최대 80자로 제한한다. 본문은 자르지 않으며 UTF-16 surrogate 쌍 경계를 보존한다. 체크리스트 판정도 문단 전체 대신 앞 두 글자만 읽는다.
2. 테마 접근마다 Brush/FontFamily를 생성했다. 색상 브러시는 Freeze한 객체로 공유하고 글꼴도 재사용한다. 같은 종이색을 다시 선택하면 변경 이벤트를 발행하지 않는다.
3. 모든 표시 메모의 자동 저장 타이머가 변경이 없어도 250ms 간격으로 깨어났다. 저장 완료 시 멈추고 새 변경에 다시 시작한다. 실패 재시도와 저장 중 새 변경 처리는 유지했다.
4. 저장 실패 뒤 새 입력이 실패 안내/재시도 버튼을 숨겼다. 실패 상태를 저장 성공까지 유지하며 재시도 중에도 표시한다. 최신 본문 보존·복구 검증을 확장했다.
5. 이동·색상 변경·동일 레이아웃 재확인에도 GDI 창 영역을 다시 만들고 저장 변경을 발행했다. 영역은 HWND별 크기/배율이 달라질 때만 교체하고, 저장 좌표가 같으면 변경을 발행하지 않는다. 창 위치 갱신은 SWP_NOZORDER로 다른 자식 창의 표시 순서를 바꾸지 않는다.
6. 로컬 시험 업데이트는 외부 피드의 제품/버전 및 파일 해시만으로 ZIP 내부 구조까지 확인하지 못했다. 다운로드 검증 후와 적용 직전에 UpdatePackageValidator로 캐시를 검사한다. 다운로드 이후 검사는 작업 스레드에서 수행한다.

## 성능 측정

선택 실행 `--performance-probe`는 가짜 8만 자 본문에 20회 워밍업 후 200회 입력한다. 다른 프로세스에 저장한 기준 0.9.0과 새 0.9.1을 같은 장비에서 차례로 실행했다. UI 스레드 할당량은 GC.GetAllocatedBytesForCurrentThread로 측정하며 프로세스 상주 메모리와 구분한다. 시간은 한 쌍의 재측정 표본으로 장비/실행 상태에 따라 달라진다. 강제 GC는 시험 도구에서만 사용하며 앱에는 추가하지 않았다.

| 작업 | 0.9.0 소요 시간 | 0.9.1 소요 시간 | 0.9.0 할당 bytes | 0.9.1 할당 bytes |
| --- | ---: | ---: | ---: | ---: |
| 8만 자 메모 200회 입력 | 430.43ms | 146.21ms | 378,488,640 | 112,786,560 |
| 제목 재계산 200회 | 191.47ms | 105.59ms | 165,179,680 | 100,856,960 |
| 테마/글꼴 조회 10,000회 | 17.16ms | 1.09ms | 2,901,168 | 80 |

입력 할당량은 **70.2% 감소**했다. 초기 표본도 378,488,640→112,786,560 bytes로 같았다(시간 410.65→186.33ms). 테마의 80 bytes는 측정용 Stopwatch 등 공통 비용을 포함한다. 아직 문서 길이에 비례하는 WPF TextRange 읽기는 남아 있으므로 모든 입력 크기에서 일정 비용이라고 주장하지 않는다.

## 보안 점검

- 기존 저장 루트/ID·스키마/본문 크기 검증, 재분석 지점 거부, DPAPI CurrentUser·암호화 임시/백업·손상 보존, 텍스트 전용 붙여넣기·드롭 차단·RTF 개체/필드/그림 거부를 코드 검토하고 기존 회귀 검증으로 확인했다. 본문·RTF를 진단 로그로 출력하지 않는다.
- 추가한 패키지 검사는 링크 경로·크기/SHA256, ZIP 경로 이탈/중복 대소문자/역슬래시/ADS/끝 점·공백/일반 DOS 장치명과 링크/특수 파일 속성, 512개 파일·파일당 256MiB·확장 합계 512MiB, 필수 exe/dll, nuspec와 sq.version의 제품/버전을 검사한다. XML은 64KiB 제한·DTD 금지·외부 resolver 비활성화다.
- 합성 ZIP의 해시를 다시 계산한 뒤 다른 제품·버전/중복 ID, 경로 이탈·충돌·필수 파일 누락, XML 외부 엔티티·과대 메타데이터·손상 ZIP을 거부했다. 이전 `artifacts/package-03d039a0613f4064af469b72acefde92/installer/WindowsMemoApp-0.7.0-full.nupkg`도 읽기 전용 검증에 통과했다. 설치·실행은 하지 않았다.
- `dotnet list WindowsMemo.slnx package --vulnerable --include-transitive --format json` 결과 앱/테스트 프로젝트의 직접·전이 NuGet 의존성에서 보고된 취약점 없음(2026-10-22, api.nuget.org 조회). 새 의존성은 추가하지 않았다. 이 조회는 .NET/Windows 전체 패치·미공개 취약점·코드 전체의 안전성을 보증하지 않는다.
- **남은 신뢰 경계:** 해시/ZIP 구조/제품 ID는 게시자 인증이 아니다. 악성 코드가 동일 제품 ID로 재패키징된 경우를 이 검사만으로 배제하지 못한다. 현재 명시적인 로컬 시험 소스만 지원하며 공개 자동 업데이트 전에 코드 서명·메타데이터 인증·키 교체 정책과 실제 설치본 적용 검증을 완료해야 한다. 같은 사용자 계정의 파일 교체 경쟁, 다른 Windows 계정의 DPAPI 실패 시험도 후속이다.

## 반복 자원 시험

`--stability-probe`는 보이지 않는 시험 부모 아래 실제 자식 HWND를 생성한다. NoteSession/NoteView/자동 저장 타이머/바탕화면 복구 타이머/알림 창을 만들고 본문·색상·접힘을 변경한 뒤 Dispose한다. 10개씩 20회 워밍업하고 100회씩 두 구간을 측정했다: **총 2,200개 세션**. 시험 데이터는 의도적으로 저장하지 않고 폐기하며 사용자 데이터 폴더에 접근하지 않는다. 실제 저장·보관·복구 동작은 별도 회귀 검증에서 가짜 DPAPI 데이터로 확인했다.

| 시점 | 관리 메모리 MiB | Private Bytes MiB | 프로세스 핸들 | GDI | USER | 폐기 후 잔존 세션/편집기 참조 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 워밍업 200개 이후 | 1.98 | 138.44 | 461 | 44 | 18 | 기준 |
| 추가 1,000개 폐기 | 2.03 | 155.89 | 469 | 44 | 18 | 0 |
| 추가 1,000개 폐기 | 2.19 | 160.91 | 467 | 44 | 18 | 0 |

두 측정 구간은 약 34.0초/30.9초다. 잔존 참조는 WeakReference와 Dispatcher 큐 정리·시험용 전체 GC 후 확인했다. 관리 객체와 GDI/USER 핸들 누적 징후는 관찰하지 못했고 프로세스 핸들도 구간마다 증가하지 않았다. Private Bytes는 첫 구간 약 17.45MiB, 두 번째 구간 약 5.02MiB 증가했다. 증가 원인이 모두 캐시라고 단정하거나 완전한 무누수를 판정하지 않는다. 실제 10개 메모의 저장/숨김/복원/보관 반복, 5분 유휴 CPU 및 8/24시간 Private Bytes 추세를 후속으로 측정한다.

참고로 복구 타이머/알림 창을 제외한 선행 시험도 구간별 잔존 참조 0개, GDI 25/USER 21 동일, Private Bytes 162.70→177.46→177.82MiB였다. 위 표는 타이머/알림 창을 포함한 최종 시험으로 서로 다른 프로세스의 절대 기준값을 직접 비교하지 않는다.

## 재현 명령과 결과

```powershell
dotnet build WindowsMemo.slnx --configuration Release --nologo -p:RestoreLockedMode=true --artifacts-path artifacts/review-validation
dotnet artifacts/review-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll --shell-probe
dotnet artifacts/review-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll --performance-probe
dotnet artifacts/review-validation/bin/WindowsMemo.Tests/release/WindowsMemo.Tests.dll --stability-probe
```

최종 빌드는 같은 artifacts에서 --no-restore로 재검증해 경고/오류 0, 전체 **71개 PASS**였다. 이전 66개에 동일 레이아웃 변경 억제 1·입력 캐시/문서 교체 1·패키지 구조 검증 3을 추가했고 자동 저장 시험은 실패 안내와 타이머 수명 확인으로 확장했다. 기존 실제 비표시 바탕화면 호스트·수집·저장/복구·휴지통·보관·시작 옵션 검증도 통과했다.

사용자 앱을 종료하지 않고 별도 출력에서 수행했다. 중간에 측정 프로그램이 시험 DLL을 잠근 상태에서 재빌드한 시도가 실패해, 측정 종료 후 순차 재빌드·전체 검증·기존 패키지 검증을 다시 완료했다. NuGet/DPAPI/Windows 자원 접근이 필요한 명령은 승인된 제한 밖 실행을 사용했고 보안 설정은 변경하지 않았다.

이번 결과는 실제 Win+D/IME·혼합 DPI/탐색기 재시작/절전 복귀, 실제 설치본 간 업데이트, 코드 서명 신뢰, 다른 계정·실제 전원 중단·디스크 부족 및 8/24시간 안정성 시험의 완료를 의미하지 않는다. 사용자 메모 변경·설치·원격 게시·푸시는 수행하지 않았다.

# 검증 계획

실행 결과가 아닌 검증 체크리스트다. 구현 작업마다 아래 형식으로 결과를 기록한다.

첫 prototype 실행 결과는 [SPRINT-01.md](results/SPRINT-01.md)에 기록했다. 아래 전체 체크리스트를 모두 완료한 것은 아니다.

## 결과 기록 형식

```markdown
### 작업 / 검증 날짜
- 코드 버전 또는 작업 식별자:
- Windows 버전·빌드:
- CPU / 화면 배율 / 모니터 수:
- 실행 방법:
- 시나리오별 결과: 통과 / 실패 / 미검증
- 화면 또는 로그 증거:
- 남은 문제 및 후속 작업:
```

## 첫 prototype 수동 검증

1. 메모 하나를 열고 다른 프로그램 창으로 덮는다. 메모가 위로 올라오지 않는지 확인한다.
2. 작업 표시줄의 바탕화면 보기로 전환한다. 메모가 남아 보이는지 확인한다.
3. 메모를 클릭해 한글 조합, 줄바꿈, 선택, 복사·붙여넣기를 수행한다.
4. 선택한 글자를 굵게·색상 변경하고 글머리 및 번호 목록을 만든다. 도구 클릭 시 선택과 포커스가 유지되는지 확인한다.
5. 별도로 Win+D 전환을 수행하고 2~4를 확인한다.
6. Win+D를 다시 눌러 창을 복원한다. 메모가 다른 창 뒤에 놓이는지 확인한다.
7. 전환을 10회 반복하고 입력 또는 창 배치가 깨지는지 확인한다.

## 첫 사용 버전 수동 검증

- 여러 메모를 생성하고 각각 편집한다. 서로 내용과 서식이 섞이지 않는다.
- 저장 완료 표시 후 앱을 종료·재실행한다. 본문, 서식, 위치·크기를 복원한다.
- 닫기로 숨긴 메모를 트레이의 목록에서 다시 연다. 재실행 시 숨김 상태도 유지한다.
- 삭제한 메모를 휴지통에서 복원한다. 본문과 서식이 유지된다.
- 영구 삭제는 확인 후 수행하고 취소하면 보존된다.
- 저장 실패를 재현한다. 저장 완료로 표시하지 않고 내용이 남아 재시도 가능하다.
- 탐색기 재시작 후 부착과 한글 입력을 확인한다. 이 검증은 사용 중인 창에 영향을 줄 수 있으므로 실행 시 사용자와 시점을 조율한다.
- 로그인 자동 실행 옵션의 켜짐·꺼짐을 각각 실제 로그인에서 확인한다.
- 실행 중 앱을 다시 열어도 데이터에 쓰는 인스턴스가 중복되지 않는다.

## 자동 검증 대상

테스트 프로젝트 생성 후 실제 로직에 맞춰 작성한다.

- 서식 문서 저장·복원 왕복: 한글, 굵게, 색상, 글머리 및 번호 목록. WPF 문서 테스트는 STA 스레드에서 수행한다.
- 변경 버전 추적: 오래된 저장 완료가 최신 변경의 완료로 처리되지 않는다.
- 저장 실패와 복구: 기존 정상본 및 백업을 보존하고 손상 데이터를 덮어쓰지 않는다.
- 상태 전이: 숨김, 삭제, 복원 및 앱 재시작이 서로 다른 동작으로 유지된다.
- 저장 형식 버전: 알 수 없는 버전을 조용히 덮어쓰지 않는다.

CI에는 빌드와 실제 작성된 자동 테스트를 추가한다. Win+D, 탐색기 부착 및 IME 입력은 실제 사용 환경 수동 검증을 유지한다.

## 보안 및 안정성 검증 연결

구현 시 `SECURITY.md`의 암호화·손상 입력·경로·변조 업데이트 검증과 `STABILITY.md`의 반복·상주 검증을 같은 결과 기록 형식으로 남긴다. 테스트 데이터만 사용하며 메모리 덤프와 스크린샷에는 민감한 내용이 포함될 수 있어 공개 저장소에 자동 첨부하지 않는다.

## 미검증 환경

다중 모니터, 서로 다른 화면 배율, 모니터 제거, 가상 데스크톱, 절전 복귀 및 Windows 업데이트 후 동작은 확인된 범위만 지원 상태에 기록한다. 첫 검증 이후 우선순위를 정하며, 확인하지 않은 환경을 지원 완료로 표기하지 않는다.

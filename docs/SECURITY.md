# 보안 설계 및 배포 기준

2026-10-13 작성. 현재 prototype에 텍스트 전용 붙여넣기, 드롭 차단, 입력 및 Undo 제한을 구현하고 기본 자동 검증을 수행했다. 0.3.0에서 메모 하나의 DPAPI CurrentUser 암호화 저장·백업·손상 복구와 관련 자동 검증을 구현했다. 다른 사용자 계정 복호화 실패 등 실제 환경 시험과 업데이트는 남아 있다. 결과는 results/STORAGE-03.md를 따른다. 이 문서는 전체 제품의 예방 규칙과 향후 검증 기준이며 취약점이 없음을 보증하지 않는다.

## 2026-10-22 중간 점검

0.9.1에서 기존 DPAPI·경로/스키마·RTF·붙여넣기 보호를 회귀 검증하고 로컬 시험 업데이트 패키지 검사를 보강했다. 다운로드 후와 적용 직전에 SHA256·ZIP 경로/중복/확장 크기·필수 앱 파일·nuspec/sq.version 제품 및 버전·DTD/외부 엔티티 차단을 검사한다. 공개 취약점 조회에서 직접·전이 NuGet 의존성에 보고된 항목은 없었다(조회 시점 기준). 이것은 게시자 인증이나 모든 취약점의 부재를 보증하지 않는다. 코드 서명·메타데이터 신뢰·실제 설치본 검증은 공개 자동 배포 전에 남아 있다. [검증과 제한사항](results/REVIEW-14.md).

## 보호 대상과 신뢰 경계

보호 대상은 메모 본문·서식·휴지통·백업, 사용자 파일, 배포 패키지와 게시 권한이다. 클립보드, 디스크 파일, 업데이트 응답은 외부 입력으로 취급한다. 로컬 저장 파일도 손상되거나 교체될 수 있으므로 신뢰하지 않는다.

위협 범위는 악성·과대 입력, 잘못된 경로, 배포 파일 변조, 의존성 취약점 및 의도하지 않은 정보 노출이다. 관리자 권한 또는 같은 사용자 계정으로 이미 실행 중인 악성 프로그램을 이 앱만으로 차단한다고 주장하지 않는다.

## 기본 권한과 네트워크

- 앱은 일반 사용자 권한으로 실행한다. 바탕화면 부착을 위해 관리자 권한이나 탐색기 프로세스 주입을 요구하지 않는다.
- 첫 버전에 수신 서버, 원격 명령 실행, 플러그인 로딩을 도입하지 않는다.
- 메모 내용과 진단 데이터를 자동 전송하지 않는다. 외부 통신은 업데이트 조회·다운로드로 제한한다.
- 외부 명령을 실행할 때 메모 내용이나 임의 파일 경로를 명령 문자열로 조합하지 않는다.

## 저장 데이터 암호화: 사용자 확정

Windows DPAPI의 CurrentUser 범위를 사용한다. 0.3.0은 Windows Desktop 공유 프레임워크에 포함된 System.Security.Cryptography.ProtectedData를 사용하며 추가 패키지 의존성은 없다. JSON에 Base64로 인코딩하는 것은 암호화가 아니므로, 평문 JSON 저장안은 아래 암호화 봉투로 변경한다.

1. 메모 본문 RTF, 상태, 위치, 타임스탬프 등의 내부 레코드를 직렬화한다.
2. 직렬화한 바이트 전체를 DPAPI로 보호한다.
3. 외부 JSON에는 암호화 봉투 버전, 보호 방식 표시, 암호문만 저장한다. 파일명은 임의 ID로 만들고 제목·본문을 넣지 않는다.
4. 임시 파일과 백업은 암호화된 결과만 쓴다. 로그에도 복호화 결과를 남기지 않는다.
5. 읽을 때 파일 크기와 봉투 형식을 확인하고 복호화한 다음 내부 스키마와 필드를 검증한다.

복호화 실패는 빈 메모 생성이나 덮어쓰기로 처리하지 않는다. 원본과 백업을 보존하고 사용자에게 복구 실패를 알린다. 앱 버전과 암호화 형식을 구분하고 새 버전에서 기존 정상 암호문을 읽는지 검증한다.

이 방식은 다른 계정에서 파일 내용을 읽는 위험을 줄이지만 같은 계정의 악성 프로세스, 화면 캡처, 클립보드와 실행 중 메모리까지 보호하지 않는다. 다른 PC 이동이나 계정 복구에는 별도의 내보내기·복구 설계가 필요하며 아직 제공하지 않는다. 사용자 파일에 일반 읽기 전용 삭제를 적용하는 것과 보안 삭제는 다르며, 휴지통 영구 삭제를 완전한 흔적 제거로 표시하지 않는다.

참고: [Microsoft 데이터 보호 안내](https://learn.microsoft.com/en-us/dotnet/standard/security/how-to-use-data-protection).

## 파일 및 경로

- 저장 경로는 고정 데이터 루트와 검증된 앱 생성 ID로 구성한다. 본문·제목·파일 내부의 경로 값을 저장 대상에 사용하지 않는다.
- 쓰기·교체·삭제 전 정규화한 절대 경로가 의도한 루트 아래인지 경로 경계를 포함해 확인한다. 단순 문자열 접두사 검사만 사용하지 않는다.
- 예상하지 않은 링크·재분석 지점은 따라 쓰거나 삭제하지 않는다. 경로 변경 경쟁 조건도 고려하되 같은 계정의 악성 프로세스에 대한 완전한 격리를 주장하지 않는다.
- 한 파일 오류 때문에 나머지 정상 메모를 덮어쓰거나 전체 데이터 폴더를 삭제하지 않는다.
- JSON 깊이, 필수 필드, 스키마 버전, ID 형식, 좌표의 유한값과 범위를 검증한다. 디스크에 적힌 값을 그대로 배열·메모리 할당 크기로 사용하지 않는다.

## 서식과 외부 입력

- 첫 버전의 외부 붙여넣기는 텍스트만 받는다. HTML·XAML·XamlPackage·임의 RTF·이미지·첨부 개체의 자동 로딩을 막는다. 앱 안에서 굵게·색상·목록을 적용하는 요구사항은 유지한다.
- 외부 파일을 XamlReader.Load 등으로 객체화하지 않는다. 메모에서 스크립트·개체·명령을 실행하지 않는다.
- 저장용 RTF는 앱이 생성한 허용 서식만 대상으로 한다. 파일 읽기는 여전히 외부 입력이므로 크기 제한, 예외 처리, 복원 후 허용 문서 요소 검사와 손상 파일 테스트를 수행한다.
- 외부 서식을 보존하는 붙여넣기는 별도 요구사항과 보안 검토 없이 활성화하지 않는다. 읽어 들인 후 검사만으로 파서 이전의 위험이 사라진다고 가정하지 않는다.
- 대용량 붙여넣기는 메모에 적용하기 전에 제한한다. 거부할 때 기존 본문을 보존한다.

초기 제한 후보는 메모당 텍스트 100,000자, 내부 RTF 2MiB, 외부 암호화 봉투 파일 4MiB, JSON 깊이 16이다. 제품 지원 한도가 아니라 구현 초기값이다. 직렬화 오버헤드를 포함한 정상 데이터와 제한 초과 입력을 검증하고 조정한다. 제한을 줄일 때 기존 큰 메모를 조용히 삭제하지 않는다.

## 자동 업데이트 및 공급망

- 업데이트 주소와 허용 채널은 앱 배포 설정으로 고정한다. 메모 파일·클립보드가 이를 바꿀 수 없게 한다.
- HTTPS 인증서 검증을 우회하지 않는다. 리디렉션·최종 다운로드 주소와 다운로드 크기·시간 한도를 정책에 맞게 검사한다. GitHub 자산의 CDN 리디렉션은 실제 경로를 확인해 허용한다.
- 해시 검증은 다운로드 손상 확인이고, 같은 피드가 변조됐을 때 게시자 신뢰를 보장하는 수단은 아니다.
- 공개 자동 배포 전에 패키지·업데이트 메타데이터의 게시자 인증과 서명 검증 흐름을 확정한다. OS 또는 앱이 어디서 검증하는지, 신뢰하는 게시자/키 변경을 어떻게 처리하는지 실제 설치본으로 확인한다.
- 서명이 유효한 다른 게시자의 파일이나 변조된 메타데이터가 적용되지 않는지 확인한다. 선택한 도구가 필요한 검증을 제공하지 않으면 추가 검증 또는 MSIX 등 대안을 검토한다.
- Velopack이 기본으로 위 조건을 모두 충족한다고 가정하지 않는다. 패키징·서명과 앱 적용 전 신뢰 검증은 별도로 확인한다.
- 배포 앱에 GitHub 토큰, 인증서 개인 키 또는 CI 자격 증명을 포함하지 않는다.
- 의존성 버전을 고정하고 직접·간접 패키지를 취약점 검사한다. 지원되는 .NET 및 라이브러리 보안 패치를 유지한다.
- CI와 릴리스 권한은 최소화하고 릴리스 자격 증명은 별도로 보호한다. 저장소 보호·계정 MFA·워크플로 권한을 배포 설정 때 확인한다.
- 서명·무결성·호환성 검증 실패 시 업데이트를 적용하지 않는다. 이미 알려진 위험한 구버전은 별도 대응을 안내하며 무조건 안전하다고 표시하지 않는다.

참고: [Velopack 패키징 및 서명](https://docs.velopack.io/packaging/overview).

## 개인정보와 진단

로그에는 본문, 제목, RTF, 암호문 원문, 클립보드, 인증 토큰을 기록하지 않는다. 오류 코드·작업 종류·앱 버전 등 필요한 정보만 남기고 로그 크기·보관 개수를 제한한다. 오류 예외에 사용자 내용이 섞이는지도 검사한다.

메모리 덤프는 본문과 복호화된 데이터를 포함할 수 있다. 누수 검증은 가짜 데이터로 수행하고 덤프·스크린샷은 Git이나 공개 이슈에 자동 업로드하지 않는다.

## 완료 및 배포 조건

- 암호화 본문·백업·임시 파일에서 테스트용 평문이 발견되지 않는다. 다른 Windows 계정의 복호화 실패는 별도 테스트 계정 환경에서 확인한다.
- 잘못된 암호문·스키마·초과 입력을 거부하고 원본을 보존한다.
- 텍스트 이외의 외부 붙여넣기·객체 로딩·메모를 통한 실행이 차단된다.
- 루트 밖 쓰기·삭제가 되지 않는지 임시 시험 데이터로 검증한다.
- 업데이트 변조·다른 게시자·인증서 오류를 거부한다. 미검증이면 공개 자동 배포를 완료 처리하지 않는다.
- 도입 의존성과 변경 코드의 보안 검토 결과를 남긴다. 알려진 악용 가능 취약점은 수정하거나 배포를 보류하고 이유를 기록한다.
- 보안 검사 결과와 제한사항을 기록하고 출시마다 관련 항목을 재확인한다.

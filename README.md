# Windows 데스크톱 메모

**Win+D를 눌러도 바탕화면에 남아 있는 Windows 메모 앱입니다.**

다른 프로그램을 사용할 때는 창 뒤에 놓이고, 바탕화면 보기에서는 메모를 바로 확인하고 편집할 수 있도록 만들고 있습니다. C#과 WPF로 개발하며 메모는 이 PC에 저장합니다.

> 현재 버전은 **0.9.4 prototype**입니다. 저장 실패 중에는 메모를 접아 오류 안내와 재시도 버튼을 숨길 수 없으며, 저장에 성공하면 다시 접을 수 있습니다. 초기 바탕화면 대기·탐색기/절전 복귀 시 연결 복구와 임시 창 배치 저장을 유지합니다. 실제 Windows UI와 설치본 업데이트 검증, 정식 릴리스는 남아 있습니다. 바탕화면 부착은 탐색기의 내부 창 구조에 의존하므로 환경에 따라 동작이 달라질 수 있습니다.

## 주요 기능

- **바탕화면 메모:** 다른 앱 뒤에 표시되며 Win+D와 작업 표시줄의 바탕화면 보기에서도 유지
- **서식 편집:** 한글·여러 줄 입력, 굵게, 검정·빨강·파랑 글자 색상, 글머리·번호 목록
- **이동과 크기 조절:** 제목 영역을 드래그해 이동하고 오른쪽 아래 손잡이로 크기 변경
- **여러 메모:** 메모의 새 메모 버튼 또는 트레이에서 독립적인 메모 생성
- **로그인 자동 실행:** 기본 꺼짐, 트레이에서 현재 계정의 등록·해제 선택
- **휴지통:** 메모를 휴지통으로 이동·복원하고 확인 후 영구 삭제 (자동 비우기 없음)
- **숨김과 재표시:** 닫기는 저장 후 숨김, 목록에서 다시 열기, 트레이에서 실제 앱 종료
- **자동 저장과 복원:** 본문·서식·위치·크기·숨김 상태를 저장하고 다음 실행에서 복원
- **로컬 암호화:** Windows 사용자 계정 범위의 DPAPI로 저장 파일·임시 파일·백업 보호
- **중복 임시 파일 정리:** 시작 시 24시간이 지난 파일 중 더 최근 정상 저장본과 내용·상태가 같은 것만 제한적으로 정리. 고유한 미완료 내용은 보존하며 자동으로 메모로 만들지 않음
- **연결 복구:** 바탕화면 연결이 끊기면 임시 창에서 편집을 유지하고 최대 10회 재연결 시도

여러 메모·트레이 구현 결과는 [검증 기록](docs/results/MULTINOTE-07B.md)을 참고해 주세요. 휴지통 구현 결과는 [검증 기록](docs/results/TRASH-08.md)을 참고해 주세요. 로그인 자동 실행 구현·검증은 [기록](docs/results/STARTUP-09.md)을 참고해 주세요. 자동 업데이트는 후속 개발 항목입니다. **닫기 버튼은 저장 후 해당 메모를 숨기며, 앱 종료는 트레이 메뉴에서 수행**합니다.

## 포스트잇 UI

- 새 메모는 320×300 DIP, 22 DIP 본문 여백, 맑은 고딕으로 표시합니다. 기존 메모의 위치·크기는 유지합니다. 디자인 값은 `Views/NoteTheme.cs`에서 관리합니다.
- 평소에는 도구를 숨기고, 마우스 또는 키보드 포커스가 들어오면 상단의 **+ · 이동 손잡이 · ⋯**를 표시합니다. 본문은 클릭해 편집하며 상단을 끌어 이동합니다. **Alt+M**으로 더보기를 열 수 있습니다.
- 더보기에서 버터·세이지·피치, 체크리스트, 접기, 보관하기와 기존 글자 서식을 선택합니다. 제목은 본문 첫 줄에서 가져옵니다. 상단 더블클릭으로 접기·펼치기를 전환합니다.
- 체크리스트는 현재 문단에 추가합니다. 체크 기호를 클릭하거나 **Ctrl+Enter**로 완료 상태를 바꾸며 Enter로 다음 항목을 만듭니다. 체크 상태도 본문 RTF에 저장합니다.
- **보관하기**는 숨기기·휴지통과 구분합니다. 트레이의 **보관 실행 취소**로 가장 최근 보관을 되돌리고, **보관함**에서 이전 보관 메모를 복원합니다. 보관함은 재실행 후에도 유지하며 실행 취소 기록은 현재 실행 동안만 유지합니다.
- 저장 실패와 재연결 오류는 숨기지 않습니다. 접힌 메모에서 오류가 발생하면 펼쳐 안내와 재시도 버튼을 표시합니다.

메모·목록 UI는 기존 **WPF**를 유지했고, WinForms는 기존 트레이에서 사용합니다. 이미지 배경이나 새 UI 프레임워크는 사용하지 않습니다. [구현·검증 및 수동 확인 항목](docs/results/POSTIT-13.md).

## 시작하기

### 준비 환경

- Windows 11 x64: 현재 검증 대상
- [.NET 10 SDK](https://dotnet.microsoft.com/download/dotnet/10.0): 프로젝트는 SDK 10.0.401을 기준으로 동일 기능 대역의 최신 패치를 허용
- C# + WPF, 대상 프레임워크 `net10.0-windows`

Visual Studio에서는 `WindowsMemo.slnx`를 열고 `WindowsMemo`를 시작 프로젝트로 선택합니다. 명령줄에서는 Windows Desktop 타기팅 팩을 포함한 SDK가 필요합니다.

### 빌드와 실행

저장소를 내려받은 뒤 프로젝트 루트의 PowerShell에서 실행합니다.

```powershell
dotnet build WindowsMemo.slnx --configuration Release
.\src\WindowsMemo\bin\Release\net10.0-windows\WindowsMemo.exe
```

바탕화면 부착을 제외하고 편집·저장을 확인하려면 일반 창 진단 모드를 사용합니다. 이 모드는 별도의 메모 파일을 사용합니다.

```powershell
.\src\WindowsMemo\bin\Release\net10.0-windows\WindowsMemo.exe --window
```

`dotnet`을 찾지 못하면 SDK 설치 후 PowerShell을 새로 열어 주세요. 기본 설치 경로는 `C:\Program Files\dotnet\dotnet.exe`입니다. 편의 명령은 [scripts/dev.ps1](scripts/dev.ps1)에서 확인할 수 있습니다.

## ZIP 패키지 만들기

프로젝트 루트 PowerShell에서 실행합니다. 앱 버전은 공통 설정에서 읽으며, 현재 앱 버전은 0.9.4입니다.

```powershell
.\scripts\package.ps1
# 로그인된 Windows 세션에서 바탕화면 호스트 검증까지 포함하려면:
.\scripts\package.ps1 -ShellProbe
```

Release 빌드와 검증 후 Windows x64 publish 결과를 `artifacts/package-GUID` 아래 ZIP·SHA256 파일로 만듭니다. 매번 별도 폴더를 사용하며 기존 패키지를 덮어쓰지 않습니다. ZIP에는 실행 파일, 런타임 설정, 시작 안내와 파일별 해시·버전·소스 상태 manifest만 포함합니다. 사용자 메모와 테스트 데이터는 포함하지 않습니다.

ZIP 전체를 풀고 `WindowsMemo.exe`를 실행합니다. **.NET 10 Desktop Runtime x64가 필요**하며 런타임을 포함한 패키지는 아닙니다. 자동 실행 등록 후 폴더를 옮기면 다시 등록해야 합니다. 실제 압축 해제본의 UI 실행은 검토 대기입니다.

`scripts/verify-package.ps1 -ZipPath <ZIP 경로>`로 구성과 해시를 확인하고, `scripts/test-package.ps1 -ZipPath <ZIP 경로>`로 변조·위험 경로 거부를 확인할 수 있습니다. 해시는 손상 확인용이며 게시자 서명을 대신하지 않습니다.

[Build prototype ZIP](.github/workflows/package.yml)은 GitHub Actions 수동 실행으로 다운로드용 ZIP과 체크섬을 14일 보관하도록 구성했습니다. GitHub Release 게시·설치·자동 업데이트는 수행하지 않습니다. 상세는 [패키징 검증 기록](docs/results/PACKAGE-10A.md)을 참고해 주세요.

## prototype 설치 파일 만들기

```powershell
.\scripts\package-installer.ps1 -ShellProbe
```

ZIP 검증 후 Velopack으로 설치 EXE, full 업데이트 패키지와 피드를 `artifacts/package-GUID/installer`에 만듭니다. 설치 루트는 `%LOCALAPPDATA%\WindowsMemoApp`, 메모는 기존 `%LOCALAPPDATA%\WindowsMemo\Notes`로 분리합니다. .NET 10 Desktop Runtime x64가 없으면 설치기가 다운로드하도록 설정했습니다. 설치기는 완료 후 앱을 실행합니다.

`scripts/verify-installer.ps1 -ReleaseDirectory <폴더> -ExpectedVersion 0.9.4`으로 파일·피드·payload 해시를 검사하고, `scripts/test-installer.ps1 -ReleaseDirectory <폴더>`로 변조 거부를 확인합니다. [수동 installer CI](.github/workflows/installer.yml)는 artifact만 생성합니다. **서명되지 않은 prototype이며 실제 설치·제거·버전 간 업데이트 검증은 남아 있습니다.** 기존 0.7.0 산출물은 [검증 기록](docs/results/INSTALLER-10B1.md)을 참고해 주세요.

## 로컬 시험 업데이트

설치본을 종료한 후 설치된 실행 파일에 시험 폴더를 지정합니다. 폴더에는 신뢰하는 로컬 빌드의 `releases.win.json`과 더 높은 정식 버전의 full nupkg를 둡니다. 0.7.0에는 업데이트 UI가 없으므로 이 경로의 실제 시험에는 0.8.0 이상 설치본 두 버전이 필요합니다.

```powershell
& "$env:LOCALAPPDATA\WindowsMemoApp\current\WindowsMemo.exe" --update-test-source 'C:\UpdateTest'
```

트레이의 **업데이트 확인 (로컬 시험)**으로 다운로드하고, **저장 후 업데이트**를 선택해 확인하면 모든 메모를 저장한 뒤 재시작합니다. 저장 또는 적용 요청에 실패하면 편집기를 유지합니다. 다운로드만으로 적용하거나 앱 시작 때 자동 적용하지 않습니다. 일반 실행·로그인 실행에서는 시험 메뉴가 없으며 ZIP·진단 모드의 업데이트 시험은 지원하지 않습니다. 시험 폴더는 실행 인수로만 지정하며 로그인 옵션에 저장하지 않습니다.

서명되지 않은 로컬 시험용입니다. 원격 주소·다른 제품·시험판·delta 패키지는 받지 않습니다. 피드 1MiB·100항목, 패키지 256MiB 제한과 경로·크기·SHA256 검사를 적용합니다. 해시는 게시자 인증을 대신하지 않습니다. 공개 자동 업데이트와 설치본 간 데이터 보존 검증은 후속입니다. [구현·검증 기록](docs/results/UPDATE-10B2A.md).

## 사용 방법

1. 바탕화면의 메모를 클릭해 내용을 입력합니다.
2. 글자를 선택하고 서식 버튼으로 굵게·색상·목록을 적용합니다. 외부 붙여넣기는 텍스트만 허용합니다.
3. 제목 영역과 오른쪽 아래 손잡이로 위치·크기를 조절합니다.
4. **새 메모**로 메모를 추가합니다. **목록** 또는 트레이 아이콘 더블클릭으로 저장된 메모 목록을 엽니다.
5. 아래쪽의 **저장 완료** 표시를 확인합니다. 닫기를 누르면 해당 메모를 저장한 뒤 숨깁니다.
6. 숨긴 메모는 목록에서 선택하고 **선택한 메모 열기**로 복원합니다. 마지막 메모를 숨겨도 트레이는 남습니다.
7. 메모 또는 목록에서 **휴지통으로 이동**을 누릅니다. 트레이의 **휴지통**에서 복원하면 숨김 상태로 메모 목록에 돌아옵니다. **영구 삭제**는 확인 후 본체·백업·손상 보존본을 삭제하며 되돌릴 수 없습니다. 휴지통은 자동으로 비우지 않습니다.
8. 자동 실행을 사용하려면 트레이의 **로그인 시 자동 실행**을 클릭하고 등록을 확인합니다. 다시 클릭하면 해제합니다. 일반 창 진단 모드에서는 변경할 수 없습니다. 실행 폴더를 옮겼다면 이전 경로 등록을 해제하고 새 위치에서 다시 켭니다.
9. 앱을 끝내려면 트레이 아이콘을 오른쪽 클릭하고 **모든 메모 저장 후 종료**를 선택합니다. 다시 실행하면 표시 중이던 메모만 자동으로 엽니다.

입력·서식·위치 변경 후 약 0.5초가 지나면 자동 저장합니다. 계속 입력하는 동안에도 최대 대기 시간 5초를 기준으로 저장을 시도합니다. 저장 실패 시 내용을 유지하고 재시도 버튼을 표시하며, 저장에 실패하면 숨김·앱 종료를 취소합니다. 강제 종료나 정전 직전의 미저장 변경까지 보존하는 것은 보장하지 않습니다.

자동 실행 체크는 앱의 등록 상태를 나타냅니다. Windows 시작 앱 설정이나 정책에서 별도로 차단할 수 있습니다. 현재 빌드 폴더의 실행 파일을 등록하므로 해당 폴더를 이동·삭제하면 자동 실행이 동작하지 않습니다. 로그인 실행은 숨긴 메모를 그대로 숨기며, 전부 숨김이면 목록을 자동으로 열지 않고 트레이에 남습니다.

## 저장과 백업

데이터 폴더는 `%LOCALAPPDATA%\WindowsMemo\Notes`입니다. 일반 창 진단 모드는 그 아래 `Diagnostic` 폴더를 사용합니다. 파일명에는 메모 내용이 들어가지 않습니다.

- 본문·서식·위치·크기·숨김 상태를 암호화해 저장합니다. 외부 서버나 API로 메모를 전송하지 않습니다.
- 저장 파일을 교체할 때 이전 정상본 하나를 `.bak` 파일로 보관합니다. 첫 저장에는 이전 파일이 없으므로 백업도 없습니다.
- 원본을 읽지 못하면 백업으로 복구하고 안내합니다. 이후 저장할 때 손상된 원본은 `.damaged-…` 파일로 보존합니다.
- 원본과 백업 모두 복원하지 못한 메모는 파일을 덮어쓰지 않고 목록에 복원 실패로 표시합니다. 다른 정상 메모는 계속 사용할 수 있습니다.
- 저장 스키마 4에 종이색·접힘·보관 상태를 포함하며 기존 스키마 1·2·3을 읽습니다. 기존 본문·서식·ID·경로·암호화·백업은 유지합니다. 새 형식으로 저장한 메모를 이전 앱으로 되돌리는 호환성은 지원하지 않습니다. 이전 앱의 미래 스키마 거부로 조용한 덮어쓰기를 방지합니다.

암호화 데이터는 저장한 Windows 사용자 계정과 PC에서 사용하는 것을 전제로 합니다. 다른 PC·계정으로 옮기는 내보내기·복구 기능은 아직 없습니다. 같은 계정으로 실행되는 다른 프로그램이나 화면·클립보드까지 보호하지는 않습니다. 자세한 기준은 [보안 설계](docs/SECURITY.md)를 참고해 주세요.

## 현재 검증 범위

0.9.4의 로컬 Release 빌드와 검증 **87개**(자동 86개 + 실제 바탕화면 비표시 호스트 1개)를 통과했습니다. [저장 실패 안내·닫기·재연결](docs/results/SAVE-FAILURE-04A.md)과 [중복 임시 파일 선별·보존 검증](docs/results/TEMPORARY-04C.md)을 참조합니다. 0.9.2의 [복구 재개](docs/results/RECOVERY-03A.md), [초기 셸 부재 시 저장·복원](docs/results/STARTUP-03B.md), [임시 창 배치·수명 검증](docs/results/FALLBACK-03C.md)도 유지합니다. 아래 0.9.1 결과는 이전 버전의 검증 이력입니다.

Windows 빌드 26300, x64 환경에서 0.9.1 Release 빌드와 검증 **71개**를 통과했습니다(자동 70개 + 보이지 않는 실제 바탕화면 호스트 1개). 저장·복구·보관·입력 제한·업데이트 패키지 경계와 제품 정보 검사를 포함합니다. 0.9.0의 100/150/200% UI 렌더링 확인과 실제 호스트 부모·WS_CHILD·TopMost 미사용·접힘 검증을 유지합니다. 실제 배율 전환·IME·Win+D 입력 시험과 설치본 업데이트를 대신하지 않습니다.

중간 점검에서는 8만 자 본문 200회 입력의 UI 스레드 할당량이 약 70% 감소했습니다. 변경이 없는 메모의 자동 저장 타이머를 멈추고 저장 실패 안내를 저장 성공까지 유지합니다. 복구 타이머·알림 창을 포함한 시험 세션 2,200개 생성·폐기에서 잔존 세션/편집기 참조 0개, GDI/USER 핸들 누적 없음이 관찰됐습니다. Private Bytes 증가와 장시간 시험 제한도 함께 기록했습니다. NuGet 공개 취약점 조회에서는 직접·전이 의존성에 보고된 취약점이 없었습니다(2026-10-22 기준). [측정·보안 검토 및 남은 범위](docs/results/REVIEW-14.md).

Win+D, 실제 한글 조합, 창 복원 후 표시 순서와 바탕화면 아이콘 클릭은 0.1.0에서 사용자 확인을 받았습니다. **0.6.0의 실제 로그인·자동 실행 옵션 클릭, 휴지통·영구 삭제 확인 UI, 트레이·목록·닫기/재표시·앱 재실행, 입력·Win+D 회귀, 탐색기 재시작, 여러 모니터·혼합 배율, 가상 데스크톱, 절전 복귀, 장시간 상주 검증은 남아 있습니다.**

상세 결과는 [초기 prototype](docs/results/SPRINT-01.md), [연결 복구](docs/results/RECOVERY-02.md), [저장·복원](docs/results/STORAGE-03.md) 기록을 참고해 주세요.

## 개발과 테스트

격리된 시험 자식 프로세스만 저장 경계에서 강제 종료하고 새 프로세스로 복원하는 `--crash-probe`도 제공합니다. 8개 시나리오와 저장 완료 범위의 한계는 [중단 복구 검증](docs/results/CRASH-04B.md)을 참조합니다. Windows CI에도 별도 단계로 실행합니다.

격리된 메모 10개로 저장·숨김·보관·복원을 100회 반복하고 5분 유휴 CPU와 파일 불변성을 확인하는 도구도 제공한다. 실행 방법과 결과는 [저장 수명 측정](docs/results/WORKSPACE-12A.md)을 참조한다. 8/24시간 상주 시험은 별도다.

설치 시작 훅에 Velopack 1.2.161을 사용하며 NuGet 잠금 파일로 의존성을 관리합니다. 패키징 도구 vpk도 같은 버전으로 고정합니다. 별도 테스트 프레임워크는 사용하지 않습니다. 테스트는 `dotnet test` 대신 다음 실행 프로그램의 PASS/FAIL과 종료 코드로 확인합니다.

```powershell
dotnet build WindowsMemo.slnx --configuration Release
dotnet tests/WindowsMemo.Tests/bin/Release/net10.0-windows/WindowsMemo.Tests.dll
```

실제 바탕화면에 보이지 않는 시험 창을 생성·해제하는 검증도 포함하려면:

```powershell
dotnet tests/WindowsMemo.Tests/bin/Release/net10.0-windows/WindowsMemo.Tests.dll --shell-probe
```

저장 시험 데이터는 테스트 빌드 출력 폴더 아래에 생성하며 사용자 메모 폴더를 사용하지 않습니다. 바탕화면 검증은 로그인된 Windows 세션에서 실행해야 합니다. 앱은 관리자 권한을 요구하지 않습니다.

### 프로젝트 구조

```text
src/WindowsMemo/
  Program.cs        앱 시작·복원·종료 및 단일 실행
  Views/            메모 편집기·목록과 저장 상태 UI
  Models/           저장 가능한 메모와 창 위치
  Services/         메모 작업공간·창 수명·트레이·RTF·자동 저장
  Infrastructure/   계정 암호화·파일 교체·백업 복구
  Interop/          바탕화면 부착·복구 및 Win32 연동
tests/              WPF·저장·복구 검증 실행 프로그램
scripts/            개발 편의 명령
docs/               요구사항·설계·검증 결과
```
